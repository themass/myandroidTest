# Her 执行手册：从产品定义到角色发布和全球运营

日期：2026-11-27｜状态：执行提案，任务尚未自动立项，阶段顺序不是发布时间承诺。

本文是 [全球产品与技术蓝图](2026-11-27-her-global-blueprint.md) 第 10 节的操作细化，任务 ID 与其保持一致；选型依据见 [开源调研](../research/2026-11-27-avatar-open-source-survey.md)、[补充调研](../research/2026-11-27-avatar-open-source-followup.md)，生产控制面细节见 [Hermes 工作台设计](../superpowers/specs/2026-11-27-hermes-live2d-production-design.md)。蓝图中 27 项均在本文展开。所有技术路线、顺序、阈值和负责人角色属于建议，除明确说明的已确认约束外，不代表产品决定或已有实现。

## 1. 建立任务系统与统一验收口径

1. 为每个蓝图任务建立父任务；以下编号如 `P0-03.a` 可作为子任务。每条记录写入实际负责人、协作人、目标版本、依赖、输入版本、预计工作量、状态、验收人及证据链接。负责人未任命时写“待指派”，不要把职能名称当作已承诺的人。
2. 状态采用 `TODO → READY → IN_PROGRESS → IN_REVIEW → PASS`；测试实际失败标 `FAIL`，缺前置或无法测标 `BLOCKED`，写原因、解除条件和责任人。测试通过但尚未并线或真机复测时，不得标整体 PASS。重新执行时关联新的版本和证据，保留旧记录。
3. 每个执行记录至少包含：问题和目标、输入及版本、逐步操作、预期、实际、证据、适用范围、失败或回滚方法。截图／视频和日志避免包含用户隐私及凭证；涉及真人录制先确认授权。
4. 所有前置验证均以实际目标分支、服务和资源版本为准。现存浏览器样件、历史验收及 SDK 接口只作为线索；设备验收记录 APK commit、构建方式、型号、系统、网络、账号状态和资源 hash。V2279A 安装由协调会话独占；只从 `weifu-refactor` 最新 tip 现场构建，不复用旧 APK，不擅自 bump versionCode。
5. 保留既有 UI；衣橱以 `wardrobe-spec` 为唯一事实源，预览与已保存选择分离，变体必须指向实际存在且已验证的模型绑定。视觉效果使用独立叠加层和 `cmp.cue`；互斥、回退等纯决策逻辑先写失败测试。全程不使用 Docker。
6. 立项时以代表性素材和设备先测基线，由对应负责人确定可复现阈值、停止条件与复审日期；本文不虚构帧率、延迟、盲测胜率、工期或成本目标。

- **G0 基线**：目标分支与设备矩阵、角色 brief/权利、现状证据可追溯；尚未确定的市场或门槛明确列为阻塞项。
- **G1 首个角色**：原创资产、真实服务、目标设备、视觉盲测与降级闭环均有证据；任何缺项记录 FAIL/BLOCKED，浏览器样件不能替代。
- **G2 个性化**：记忆权限和删除、真实衣橱、独立特效，以及声音馆七项各自完成并线和适用的设备验收。
- **G3 生产发布**：控制面、人工审核、资产权利、不可变候选、灰度、回滚和撤权演练完成；允许其他方向继续实验，但不得宣称生产发布能力完成。
- **G4 地区/生态**：对应地区的语言、政策、服务、运营和客服准备完成，才逐地开放；公开创作另过权利和治理门。

## 3. P0：从真实现状到首个可验收角色

### P0-01 首发场景、地区、语言和设备｜产品、研究、运营

- **输入**：现有用户场景、全球愿景、服务可用性和目标设备数据。**前置**：无需等待代码。
- **步骤**：a. 访谈或整理用户任务，区分短文字、长对话、实时语音和视觉陪伴；b. 为候选地区收集语言、网络、provider、年龄规则、商店与客服限制；c. 为候选设备收集 Android 版本、GPU/WebView、内存和网络分布；d. 记录 Android 优先和首批市场作为建议，列替代方案、取舍、决定人；e. 在任务系统冻结本次验收矩阵及修订流程。
- **产出**：场景优先级、地区／语言／设备矩阵、待决定事项和数据来源。**验收**：每个首发场景有成功及失败路径；每个设备层有可获得的实机或明确 BLOCKED；没有把建议写成用户确认。

### P0-02 原创角色 brief、视觉参考与权益｜产品、美术、权益

- **输入**：P0-01 暂定场景，用户提供的视觉目标、授权来源。**依赖**：最终市场限制取 P0-01。
- **步骤**：a. 写角色个性、称呼、风格、多语言表达与不应出现的行为；b. 固定合法参考和目标画面、镜头、分辨率；c. 列表情、动作、口型、发型服装、遮挡与交付格式；d. 登记作者、模型、参考、音乐、字体、肖像及地域/期限/商用权；e. 设计随机、匿名、同条件的盲测题组与评分记录，组织独立评审。
- **产出**：角色 brief、参数/动作清单、权利台账、盲测方案。**验收**：每份源素材有可核对的授权或标记禁止进入发布；评审材料能复现比较条件；不把机器人样件当最终品质证据。

### P0-03 目标分支现状与设备基线｜客户端、QA

- **步骤**：a. 记录目标分支 tip、依赖版本及构建配置；b. 清点每种引擎、模型、资源种子、ABI、下载和校验路径，标记真实入口与调试入口；c. 检查干净安装所需授权文件、依赖和失败回退；d. 在协调安装窗口以最新构建执行首次启动、角色加载、退后台和重启；e. 建立缺口列表和基线测量。
- **产出**：版本化能力矩阵、构建/设备证据、缺陷台账。**验收**：每一条区分源码存在、可构建、真机实测和可发布；缺素材、许可或设备即 BLOCKED。

### P0-04 原创模型制作与导出｜美术、绑定师

- **输入**：P0-02 已过权益的 brief 和表情/服装规划。**步骤**：a. 设计可拆分图层、关节、变形和遮挡；b. 人工绘制并复核隐藏区域；c. 在固定版本编辑器中绑定参数、物理、动作与口型；d. 为实际制作的衣装配置部件和互斥，不用参数声明冒充未绘制资产；e. 归档源工程、依赖、导出、校验和授权版本；f. 在官方预览及目标 runtime 检查动作与极端姿态。
- **产出**：可编辑源文件、版本化运行时包、参数表、权利和截图。**验收**：表情与动作清单逐项有对应资源，遮挡和变形经美术复核；未完成项不对用户开放。

### P0-05 加载、表现、热切换与回退｜Android、QA

- **依赖**：P0-03/04。**步骤**：a. 用真实模型核查引擎接口与资源绑定；b. 定义临时下载、完整性检查、原子启用与旧版本保留方案，先确认现有实现的覆盖范围；c. 接入口型、表情及模型切换，明确渲染线程与生命周期；d. 注入缺文件、错误 hash、损坏包、网络中断和切换失败；e. 测冷启动、切后台、旋转、销毁重建和低内存。
- **产出**：实现及回归用例、版本化资源、设备记录。**验收**：有效模型能展示和交互，坏包不替换可用版本，错误可见可恢复；每项在目标端有证据。

### P0-06 真实会话、字幕与打断｜语音、后端、Android

- **步骤**：a. 描述会话和 turn 状态、超时、取消和重连；b. 固定真实 STT/对话/TTS/RTC 配置及权限，避免把模拟回复记作真实；c. 在客户端呈现连接、聆听、处理、回答、静音和退出；d. 测用户打断、连续快速发言、迟到消息、网络切换及重连，检查旧 turn 不覆盖新 turn；e. 记录首音与整轮延迟分布、失败率及音画同步。
- **产出**：事件/状态契约、端到端记录、性能基线及问题清单。**验收**：真实服务在目标条件下完成会话；拒麦可降级文字；未复现或缺凭证如实 BLOCKED。历史预热改善未经复测不得宣称通过。

### P0-07 视觉盲测和基本信任体验｜产品、美术、QA、无障碍

- **依赖**：P0-05/06。**步骤**：a. 固定真实角色、参考、动作、镜头和设备；b. 随机匿名展示、收集独立评分与问题，不展示引擎名称；c. 检查字幕、放大、屏幕阅读、降低动态及静态降级；d. 检查 AI 身份、隐私选择和退出；e. 整理观察、样本偏差、阻塞与返工责任。
- **产出**：盲测方案、原始结果、画面证据和问题台账。**验收**：预先确定的质量门槛在足够样本下达成；未达标返 P0-04/05，不以技术能播放代替视觉达标。

### P0-08 用户头像与 Her 角色草稿边界｜产品、客户端、后端

- **步骤**：a. 列双方对象的所有者、使用位置、隐私、资源、授权与生命周期；b. 对照现有用户头像的入口和 API；c. 设计角色草稿、预览、审核、发布所需新增接口；d. 写出跨对象引用和删除行为，避免误把个人头像上传或发布为 Her 角色。
- **产出/验收**：对象关系与权限表、交互流程和接口差异；两种创建、保存和删除可独立验证。

## 4. P1：关系、个性化和声音

### P1-01 角色、实例、资源、会话契约｜后端、客户端、数据

- **步骤**：a. 以蓝图目标对象为草案，核实现有 schema 和 API；b. 定义角色身份、不可变 release、用户实例、会话与资源版本引用；c. 列读写权限、乐观并发、幂等、缺字段和旧版本行为；d. 写版本化 schema、迁移/回滚与契约测试；e. 双用户、多实例、替换模型和旧客户端联合验证。
- **验收**：接口兼容和越权测试通过；换外观或 release 不丢关系与记忆；没有把提案字段误写为线上现状。

### P1-02 用户可控记忆｜产品、后端、安全

- **步骤**：a. 定义开启/关闭、可记范围、来源、推断标记和保留策略；b. 实现展示、更正、逐条和批量删除；c. 梳理主库、检索索引、缓存、派生数据和备份生命周期；d. 在访问和检索层校验用户、角色及授权；e. 测两用户、多角色隔离、删除后检索、并发更新和恢复。
- **验收**：用户能理解并控制记忆；删除进度与限制可见，测试证明相关在线索引和缓存不再召回，备份按明确政策处理。

### P1-03 真实衣橱｜美术、Android、QA

- **步骤**：a. 盘点生产侧 `wardrobe-spec` 的 active、pending-art、pending-param 与 `verifiedFrom`，以真实文件为准；b. 将目标原创模型的可用部件/参数映射到规格，记录来源和版本；c. 先为互斥、缺失、回退、兼容、预览/保存隔离编写失败测试；d. 实现引擎适配与迁移，移除对 ATRI 的错误泛化；e. 在目标设备检查每套真实服饰、组合、姿态、重启恢复及资源缺失。
- **验收**：至少一个非 ATRI 原创模型完整通过；规格外及 pending 项不展示为可用；贴图或部件不存在不能凭参数创造衣服。

### P1-04 舞台特效与锚点｜Android、视觉、QA

- **步骤**：a. 固定 `cmp.cue → AvatarEventMapper → Gesture/gestureSeq → StageEffectMapper → LottieFxLayer` 的当前实现和版本；b. 定义事件白名单、频率限制、重复/过期 cue 处理及关闭开关；c. 验证独立层的前后关系、透明、触控和资源回收；d. 对照当前部分固定视口坐标，设计并测试不同模型比例、姿态及窗口尺寸的锚点；e. 在目标机记录性能与降级。
- **验收**：效果不改原 UI、不干扰模型和输入；锚点跟随能力仅在真实通过的模型/姿态范围内宣称。

### P1-05 声音馆七项｜声音、产品、QA

逐项建立当前分支 diff、并线测试和真机证据表，保留七项范围，不用历史结果替代当前状态：

1. **完播接续**：测普通下一首、列表尾、分页加载与网络失败。
2. **四态模式**：测单曲循环、列表循环、顺序末首停止、随机，以及重启后的模式恢复。
3. **0.25–3 倍速**：测边界、越界处理、换曲/seek 与持久化。
4. **前台服务和通知**：测后台/锁屏继续、通知播放暂停与上下首、退出与系统版本适配。
5. **声音收藏**：核对 `tofavorite(SOUND)` 既有本地收藏链；测收藏、取消、列表显示和本地重启恢复，勿假设服务端同步。
6. **Wi-Fi 提示**：对照当前用户设置和既有语义，测非 Wi-Fi 准备完成后的暂停提示、用户确认与取消、页面重进、播放中切网；不另造全局策略。
7. **歌词／实时字幕**：确认当前音频源、ASR 配置、开关、暂停、换曲、seek/倍速和页面退出；历史路径为曲目音频并行解码并送实时 ASR，非已证实的 LRC 数据源，也非麦克风采集。核对当期网络与隐私处理，缺数据或凭证标 BLOCKED。

**验收**：每项分别给 PASS/FAIL/BLOCKED、代码版本、测试和真机结果；设备窗口依协调会话执行。

### P1-06 主动互动｜产品、后端、QA

- **步骤**：a. 明确用户主动开启、语言、时区、免打扰、频率和退出策略；b. 定义发送前授权与取消检查、去重和失败重试；c. 实现未响应降频、撤销立即生效；d. 测时区变化、跨日、并发、退订、被封禁及设备离线。
- **验收**：未经开启不发送；每次发送有可审计的授权和策略版本，不以制造依赖为优化目标。

## 5. P2：内容工坊与可撤回发布

### P2-01 生产控制面｜后端、平台、安全

- **步骤**：a. 建立项目、角色、成员与最小权限模型；b. 定义任务状态转换、输入版本、幂等键、租约、超时和取消；c. 建立不可变工件、hash、来源和审计；d. 让数据库保存权威状态，队列仅调度；e. 测 worker 崩溃、重复投递、并发审批、重试及恢复。
- **验收**：每次任务可追到输入、工具版本和输出；失败不会覆盖批准版本，越权和重复处理有测试。

### P2-02 Hermes 受控 worker｜工具、平台、安全

- **步骤**：a. 固定执行器和工具版本，验证是否能在允许的非 Docker 环境执行；b. 限制身份、文件目录、网络、运行时长、资源与可调用工具；c. 明确输入输出契约和任务心跳、租约、取消、重试；d. 模拟异常退出和恢复；e. 测试确定性工具输出并人工复核生成建议。
- **验收**：worker 无直接审批/发布权限，能恢复或明确失败；如无法满足约束则记录替代执行器，不把 AI 当自动专业绑定师。

### P2-03 一套授权资产走完全流程｜制片、美术、QA

- **步骤**：a. 选择有完整权利的 brief 和源文件；b. 创建任务、人工分层/绑定、导出运行包；c. 固定检查器校验清单、参数、文件安全、hash 与权利记录；d. 用真实 runtime 与目标设备验画面；e. 人工审核并形成不可变候选。
- **验收**：从 brief、人工操作、工具、工件到复核可追溯；失败能退回具体阶段，源文件不被覆盖。候选通过不等同已发布。

### P2-04 版本、审批、灰度和撤权｜发布、SRE、权益

- **步骤**：a. 定义 manifest schema、依赖、兼容范围、校验和/签名、权利有效期和回滚版本；b. 实现 `draft → producing → candidate → qa → approved → staged → published → retired/revoked` 的授权状态迁移与审计；c. 配置独立审批及按地区/设备/比例灰度；d. 演练坏包、CDN 故障、老客户端、签名错误和回滚；e. 演练撤权、缓存失效、离线资源和用户替代体验。
- **验收**：审批前不可见；失败保留可用版本；撤回不删除用户关系和私有记忆，所有操作有证据与责任人。

### P2-05 第三方项目治理｜安全、工程、权益

- **步骤**：a. 按需求建立候选清单和既有能力对照；b. 固定仓库、commit、构建环境及直接/传递依赖；c. 分别核查代码、编辑器、runtime、模型、数据、字体、声音、服务条款及地域用途；d. 在隔离权限下评估不可信输入、路径穿越、解压限制、资源和网络行为；e. 做同输入 PoC、设备/性能验收；f. 记录 NOTICE、SBOM、维护人、升级和替换策略。
- **验收**：无权利证明不能进入发布；Live2D Core 与 Framework、Spine runtime 和素材分开审核；未采用的候选保留实验结论，不成为强制依赖。

## 6. P3：媒体能力与可扩展实验

### P3-01 本地相机特效与美颜｜视频、Android、隐私

- **步骤**：a. 审计 CameraX/MediaPipe 调试实验和当前本地内存处理边界；b. 制作相同授权输入的 MediaPipe 与 GPUPixel 对照，核 ABI、构建、16 KB 页、图形生命周期；c. 测脸部遮挡、旋转、多人、低光、权限拒绝及热稳态；d. 验证日志、存储与网络行为；e. 明示本地效果开关和失败降级。
- **验收**：目标设备隐私和性能证据完整；本地合成不等于对端可见。

### P3-02 同意后发送合成视频｜视频、RTC、隐私、QA

- **依赖**：P3-01 和发送用途审批。**步骤**：a. 用户分别选择相机开启和对端共享，显示发送状态；b. 设计帧合成和 LiveKit 自定义 capturer 生命周期；c. 测格式、stride、旋转、时间戳、引用与线程归属；d. 双端观察画面、音画同步、弱网、切换、退出和撤销；e. 测 CPU/GPU、延迟和热表现。
- **验收**：明确同意前无视频发送，关闭后停止；真实对端与异常场景有证据。SDK API 存在仅证明可研究，不能替代端到端测试。

### P3-03 VRM 角色、衣橱、动作和口型｜3D、美术、QA

- **步骤**：a. 选择授权样本和 Blender/VRM Add-on 固定版本；b. 导出并记录模型、贴图、表情、VRMA 和权利；c. 经 Validator 与单操作优化，逐次对照扩展、材质、骨骼及外观；d. 测衣橱、中文口型、动作和低端设备；e. 测 Android WebView/WebGL 2、透明合成、生命周期和温升。
- **验收**：任何优化导致扩展或视觉丢失则该路径失败；桌面点粒子和浏览器演示不代表 Android 体验达标。

### P3-04 粒子与诊断 A/B｜图形、视觉、性能

- **步骤**：a. 固定相同 cue、授权美术目标、分辨率、设备和动画时长；b. 对照 Lottie、Konfetti 与 three.quarks，按需补 Effekseer；c. 收集首帧、帧时间 P50/P95、CPU/GPU、内存、温升与电量；d. 检查透明、遮挡、触控、前后台与停用；e. 比较制作成本、许可和运行依赖，记录选用或不选原因。
- **验收**：可复现的同条件结果与视觉评审均有记录；减少绘制数量不能直接推断 CPU 同比例下降。

## 7. P4：区域、多端、生态与成本

### P4-01 首市场地区矩阵｜国际化、法务、运营

- **步骤**：a. 每地区列语言、STT/TTS/对话、RTC、数据位置、支付、年龄和商店约束；b. 母语人员检查文案、称呼、语音、字幕、RTL 和文化问题；c. 校验适用政策、举报和危机资源、客服和值班；d. 以小范围灰度验证服务质量与回退。
- **验收**：每个启用地区有核验来源、负责人、复审日期和关闭机制；缺项则该地区 BLOCKED，不把一地结果外推全球。

### P4-02 Web 工作台和多端实例｜平台、客户端、QA

- **步骤**：a. 按 P1-01/P2-04 定义各端权限及能力矩阵；b. 实现或评估角色实例、资源版本和用户选择同步；c. 验证离线、冲突、旧客户端、撤权和设备恢复；d. 对 Web 工作台的上传、预览、审批入口分别做权限和兼容测试。
- **验收**：同一实例在支持的平台状态一致，权限隔离和失败回退有证据；不宣称每端支持全部引擎。

### P4-03 从私有分享到公开生态｜产品、权益、安全、运营

- **步骤**：a. 定义上传者、被展示者、模型与声音权利证明；b. 建立审核、申诉、举报、撤权、紧急下架和客服流程；c. 验证私有默认、分享范围、滥用和恶意文件隔离；d. 明确结算、费用、地区可用性及责任；e. 进行模拟侵权与事故演练。
- **验收**：治理、运营和地区门全部就绪才开放公开 UGC；私有草稿不默认公开。

### P4-04 单位成本与容量｜财务、SRE、语音

- **步骤**：a. 使用真实采样和供应商合同分解 STT、模型、TTS、RTC、存储及流量；b. 分语言、设备和场景测量平均与尾部成本；c. 对并发、地区出口、故障转移及峰值做容量实验；d. 设计告警、限流、降级、预算和回滚；e. 在不牺牲基本隐私控制的前提下评估商业方案。
- **验收**：假设、数据时间、成本公式、敏感性和缺口可复核；没有真实数据时为估算或 BLOCKED，不伪造报价。

## 8. 首次迭代的执行工作包

以下是建议的首次执行批次，不预设人员、时长或同时上线；在任务系统逐条领取并按门禁推进。

1. **产品与权益**：创建 P0-01、P0-02、P0-08；产出首发矩阵草案、角色 brief、权利链和头像／角色对象对照。市场未决定时只完成不依赖其结果的工作。
2. **工程基线**：创建 P0-03 与 P0-06 的现状调查；记录主线 commit、构建依赖、真实服务配置、引擎入口和缺口；设备安装交协调会话。
3. **视觉素材**：基于已过权益审核的 brief 启动 P0-04，先交付源文件、参数与动作清单，再输出首个真实模型；P0-05 在获取导出后开展设备接线。
4. **质量基线**：建立盲测协议及证据模板；以真实角色和同条件参考执行 P0-07。缺模型、参考权利、目标机或服务时记录 BLOCKED。
5. **并行对账**：P1-05 列齐声音馆七项并读取当前实现及历史记录；只在对应代码已并线、测试和设备结果齐备时标 PASS。P1-01 可先盘点已有契约，迁移设计与角色生产保持版本一致。
6. **评审与下一批**：以 G0/G1 证据决定缺口和负责人；P1 以真实模型和用户实例为输入，P2 的生产发布依据权益和首个资产闭环推进；其他候选限定实验预算和停止条件。
