## 2. 真机发现的缺陷（均已修复并提交）

| # | 现象 | 根因 | 修复 | 回归测试 |
|---|---|---|---|---|
| D1 | 编辑图片后发送，发出去的仍是**原图**，涂鸦/文字/马赛克全丢，无提示 | 渲染器对解码出的**不可变**位图 `Canvas(...)`，抛 `IllegalStateException` 被吞，退回原图 | `writableCopy()`：总是画在可写且不是调用方那张的位图上 | `PhotoRendererTest`（3 个） |
| D2 | 对话里**发图片/文件一律「发送失败」** | `BaseService().apply { setup(context) }`：apply 内 `context` 解析成 `BaseService` 自己的公开字段（null），等于 `setup(null)`，构造请求时 NPE | 改 `also { it.setup(context) }` | `ChatRepositoryWiringTest` |
| D3 | 点「旋转」预览不动 | 编辑器只记录操作，预览从不转 | `graphicsLayer` 同时作用于图片和标注 | 真机截图对比 |
| D4 | 旋转 + 镜像后，标注偏离照片上的物体（约 60px） | 图片「先转后镜像」、标注「先镜像后转」，顺序不一致 | 统一为「先镜像、再旋转」 | `annotationsStayOnTheSameSpotUnderRotateAndFlip` |
| D5 | 转 90° 后点「镜像」，看到的是上下翻转 | 镜像在原图坐标里做 | `flipHorizontalOnScreen()` | `flipMirrorsWhatTheUserSeesAfterRotation`（已验证在旧实现上失败） |
| D6 | 马赛克预览是一块半透明白色，看不出是马赛克 | 预览与导出用了不同的画法 | 预览按导出同一算法画方块 | 真机截图对比 |

另有 3 个在合并阶段发现并修复（见提交 `f7b0d7f9`、`c05ca758`）：
拍照解题服务端 `errno` 被网络层吞掉；可选表单字段被序列化成字面量 `"null"`；对端分支带来的 4 处编译错误。

## 4. 服务端检查（testserverV，已部署）

探针：`scripts/devicetest/photosolve_probe.py`（需构造 UA 签名并解密响应，裸 `curl` 会得到 `errno 10000`，这不是故障）。

| # | 发现 | 影响 | 建议 |
|---|---|---|---|
| V1 | `photosolve.maxBytes=5`。代码把它当**字节数**读，任何图片都超限，返回 `40003 单张图片不能超过 0MB` | **拍照解题 100% 失败** | 改成 `5242880`，或删掉这一行用默认值 |
| V2 | `photosolve.doubao.model= ep-2024xxxx-xxxxx` 是模板里的占位符；`apiKey` 只有 3 个字符 | 过了 V1 之后调模型必然失败 | 填真实接入点 id 和密钥 |
| V3 | `health.json` 在 V2 的情况下仍返回 `configured:true`（只检查非空） | 自检会谎报就绪，部署后看不出问题 | `isConfigured()` 至少排除形如 `ep-xxxx` 的占位符，或加一次真实的轻量调用 |
| V4 | `health.json` 响应里 `maxBytes` 是字符串 `"5"`，其余是数字 | 类型不一致，印证 V1 | 同 V1 |

> V1/V2 是**部署配置**问题，我没有改服务端 `secrets.properties`（里面是你的密钥）。
> V3 是代码缺陷，在服务端仓库，本次未改。
