# 数字人个性化 · 头脑风暴设计

日期：2026-11-21 · 状态：草案，快赢项已随文实现

## 意图与为什么

用户问题原样收敛成四件事：① 3 个数字人的背景色可设置（一个颜色板）；② 人物可点击、点击有反应；③ 人物有动作指令（转身、移动）；④ 形象可选、声音怎么绑定人物、切人是否切声。再往上是一句「非常非常多可以想象的事情，发散思考」。

目标不是把清单做完，而是把「哪些今天就动、哪些要服务端、哪些要素材、哪些是产品决策」分开放好。

## 现状事实（读码结论，非猜测）

- **通话页背景**：写死在 `CallColors`（`CompanionCallScreen.kt:206`）——竖直渐变 `BackdropTop/Mid/Bottom` + 两团径向光晕（主光晕随电平呼吸，幅度 0.55→0.72）。这层是「页面氛围」，可配置成本极低。
- **人物画面内的背景**：Duix 素材烤进模型的，客户端换不掉；换背景要走素材管线（绿幕/换底），不是 App 任务。
- **人物可点击**：协议已预留 `AvatarCapability.TOUCH_TAP / TOUCH_DRAG`、`AvatarCommand.Gaze`（注释写明 P3b 由拖动驱动）。缺的是通话页把手指事件发进去 + 点击后的反馈定义。
- **动作指令**：`AvatarCommand.Gesture(id)` 已定义，**Duix 引擎已实现**（`DuixDigitalHumanEngine.kt:72` → `rt.startMotion(motionId)`）；Tao/Live2D/Simple 忽略。缺 motionId→动作清单、agent 下发通道、界面入口。
- **声音绑定**：在服务端角色配置上（`voice_ref={"provider":"volcengine","voice_id":…}`），建会话只传 `character_id` → **换人即换声，已经是现状**。客户端只读 `voice_label` 展示。换某个人声音 = 改服务端角色数据。
- **通话页外观持久化**已有先例：`loadWaveOptions/saveWaveOptions`（`CompanionRoute.kt:559-591`）+ `WaveStyleMenu` 下拉。背景主题应复用这条通路，不开第二套机制。

## 设计（按层）

### L0 快赢 · 纯客户端，本轮实现

**A. 通话页主题色板（「背景色可设置」的正确落点）**
- 新增纯数据 `CallTheme`（id + 三档渐变 + 光晕色 + 强调色 + 底部托光色）与预设表：
  - `深海`（现配色，默认，不动原有观感）
  - `暖夜`（棕黑 + 琥珀光晕）
  - `纯黑`（OLED，光晕减半）
  - `苔原`（冷灰绿）
- `CallBackdrop` 从主题取色，不再读 `CallColors` 常量；强调色同时驱动状态点/时长色，保证「换主题=换氛围」而不是只换背景。
- 选择器并进现有 `WaveStyleMenu`：新增「背景」一栏，✓ 标记，与波形/形象同一入口；持久化走 `loadCallTheme/saveCallTheme`（同一个 SharedPreferences 模式）。
- 约束：**默认主题必须与现状像素一致**——「不要改原来的UI」对没设置过主题的用户仍然成立。

**B. 人物可点击 · 本地即时反馈**
- 触感契约纯函数 `tapFeedback(reducedMotion)`：按下缩放量与回弹时长（减弱动效 → 只淡、不缩）。
- 点击解析纯函数 `resolveTap(count, ageMs)`：单点=轻触反应；双击=动作请求（发 `AvatarCommand.Gesture`）。
- 舞台挂 `detectTapGestures`：本地先动（微缩放脉冲 + 触点涟漪，不等网络），再决定是否发指令——**反馈永远先于理解**，点了没反应是体验底线。
- 只在有数字人舞台时挂；Classic/Stacked 布局不动（保持「不改原 UI」）。Duix 舞台上的 tap 与引擎自带手势共存（tap 不消费拖拽）。
- 触觉 `HapticFeedback`（系统开了就震，关了不震）。

### L1 动作指令（客户端半 + 服务端半）

- **第一步是侦察不是编码**：用现成 rig（`DhTestAudio` 广播 → `Gesture(id)`）把每台机、每个模型号的 `startMotion` 有效 id 全扫一遍，产出「motionId → 动作 → 时长」表随包。没有这张表，一切「转身」都是碰运气。
- 客户端：`AvatarCapability.GESTURE` 已有；手势入口用**长按人物弹手势盘**（招手/点头/摇头/思考），不常驻一排按钮。
- 服务端：agent 结构化输出里开 `gesture` cue（协议早就是「指令来自结构化输出，不解析文本」，天然接得上）。
- 「移动/走动」Duix 素材里通常没有位移，只有原地动作——想要「走近」得靠机位视差（客户端缩放+平移镜头）伪造，可作为 `Camera` 指令做在渲染层，成本一天。

### L2 形象与声音（数据模型决策在先）

- 现状是 1 角色 : 1 voice_ref : 引擎由 Lab 设置选。真正的需求是 **1 人格 : N 形象 : M 音色**。
- 需要服务端角色模型加 `avatars[]`（引擎 + 资源 id）与可选 `voice_variants`（正式/气声/开心），客户端把 Lab 的「形象」菜单升成「TA 的呈现方式」列表。
- 音色试听：角色页点一下播 3 秒 sample（服务端预渲染或调 TTS 接口，一次性成本）。
- 引擎能力位（`AvatarCapability`）已经在客户端，服务端按机型能力返回可呈现列表即可。

### L3 发散的长尾（记下来就好，别现在做）

**陀螺仪关联（用户补充点名的方向）**
- **视差看屋**：倾斜手机时背景和人物分层反向微移（背景动得多、人物动得少），Duix 视频底虽换不掉，视差能伪造「你在她的房间里移动视线」。成本低：TYPE_ROTATION_VECTOR + 两级 graphicsLayer 位移，纯客户端。
- **她跟着你的朝向**：手机从正对转向侧面，她的 Gaze 跟着偏——协议里 `AvatarCommand.Gaze(x,y)` 现成，缺的只是传感器→Gaze 的映射层。竖屏通话时最有效果。
- **空间音频跟头**：人立绘在画面左，转动手机时声场像真在房间左侧（AudioEffect.PAN，纯客户端）。
- **举起/放下的仪式感**：proximity+加速度判断「拿起手机看向她」→ 她抬头看你开始待机苏醒；放下口袋 → 挂起。省电同时像「她知道你在不在」。
- **摇一摇=换人/换手势**：危险手势（误触代价高），最多作为设置里的可选项，别默认开。
- 约束：传感器全在 `SensorManager` 低频批处理（100ms 档），别 60Hz 拉满耗电；横竖屏切换要重置基准姿态。

**其余**
- 环境跟随：主题跟时间（白天/深夜）、跟角色代表色、跟情绪（她说冷，光晕变冷）——都是 L0 主题的延伸，先有主题才有这一切。
- 待机生命感：眨眼/微转头/走神后回头看镜头；情绪收回用缓动不用 `ClearEmotion` 硬切。
- 打断分层：礼貌停/皱眉停/抢话，按角色性格。
- 记住持机习惯（你总在左侧，她常年偏左看你）。
- 空间音频（人在左、声在左）。
- 低端机自动降级 Live2D，人格与声音不变（`DhEngineRegistry` swap 已支持换引擎）。
- **换角色记忆是否延续 = 产品决策，先定再动工**。
- 全身边缘：Tao 引擎在 ≥8GB 非 Kirin 机上才有戏；「换全身」的正确问法是「TA 换到哪个引擎的哪个形象」。

## 目标 / 非目标 / 反目标

- 目标：每一层单独可发布；默认观感零变化；点了必有反应。
- 非目标：本轮不碰素材管线（换人物真背景）、不碰服务端协议（只留好接口形状）。
- 反目标：常驻手势按钮条（抢戏）、给 Classic 布局塞新交互（违反「不要改原来的UI」）、在客户端存角色→音色映射（那是服务端数据，客户端硬编码过一次就会漂）。

## 留给施工者的自由度

主题的第四、五预设加什么色；涟漪颜色；手势盘出现动画——照 astryx motion token 自行定，契约测试只锁时长档位与降级规则。
