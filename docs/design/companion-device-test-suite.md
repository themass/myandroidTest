## 0. 先看这个：服务端现在是什么状态

陪伴和 agent 的公网接口**还没部署**（`/companion/*`、`/api/agent/v1/*` 在 nginx 上是 404，见 [部署方案](deployment-plan.md) §9）。
所以测试集分两个口径，脚本会自动探测并选一个，也可以 `--expect` 强制：

| 口径 | 含义 | 验收的是什么 |
|---|---|---|
| `degraded` | 服务端没部署 | **缺服务时的表现**：每页有交代（内容/空态/错误态/重试），不空白、不无限转圈、不崩 |
| `live` | 服务端已就绪 | 功能本身：偏好、事件、发消息、语音 |

两个口径的「通过」含义不同，报告里会写明口径。**degraded 下全绿不代表陪伴功能可用。**

要在 live 口径测，有两条路：先把 nginx 的两个 location 配上并部署 companion-agent；或者把手机指向本机/局域网的 companion-agent（需要改客户端 baseUrl，本测试集没做这件事）。

## 1. 开测前的检查（每条都要有输出）

| # | 检查 | 命令 |
|---|---|---|
| P1 | 手机独占。别的会话在用 `com.openapi.ks.free1` 时不要测 | `adb shell dumpsys activity activities \| grep mResumedActivity` |

脚本**只操作本包**，不会 force-stop 别的应用。杀进程的用例（C9）必须显式加 `--allow-kill`，且只 stop 本包。

## 2. 自动化部分

```bash
python3 scripts/devicetest/companion_suite.py --list           # 只列用例，不碰手机
python3 scripts/devicetest/companion_suite.py                  # 全部，自动判断口径
python3 scripts/devicetest/companion_suite.py --only C1,C2,C7  # 部分
python3 scripts/devicetest/companion_suite.py --rounds 10      # 加大反复进出轮数
```

输出在 `/tmp/companion-suite/<时间戳>/`：`report.md`（结果表）、每个用例的截图和文本快照。
退出码 0 全过 / 1 有失败 / 2 环境不满足。**SKIP 不算通过**，报告和终端都会单独提示。

| 用例 | 口径 | 检查什么 | 判据 |
|---|---|---|---|
| C1 | 任意 | 打开陪伴标签 | 不崩；页面有内容、空态、错误态或重试之一 |
| C2 | 任意 | 角色 / 她记得的 / 她的主动性 三个子页 | 能进、各自有交代、返回能回到主页 |
| C3 | live | 暂停 1 小时 → 恢复 | 出现「暂停至」；恢复后消失 |
| C4 | live | 偏好开关重进保持 | 重进页面完整（开关值靠截图人工对） |
| C5 | live | 重要日子添加/忘掉 | **当前 SKIP**：添加表单的输入框要先看一次真机界面再固化 |
| C6 | live | 发一条文字消息 | 60 秒内有新文本，且无「出了点问题」 |
| C7 | 任意 | 陪伴 ↔ 对话 反复切换 N 次 | 每轮文本序列与第 0 轮一致 |
| C8 | 任意 | 切后台 4 秒再回来 | 仍在陪伴页，内容不明显变少 |
| C9 | 任意 | 杀本包后重进 | 需 `--allow-kill`；页面有交代 |
| C10 | 任意 | 抽屉「测试」分组 / AgentChat 入口 | **SKIP**：抽屉要手势打开，转手工 M12 |
| C11 | live | 切语音模式 | 不崩（授权后的通话转手工） |

脚本的已知局限，写在这里是为了不被它的「绿」骗：

1. **按文案定位控件**，文案改了脚本就找不到。文案集中在脚本顶部的 `S` 字典。
2. **文本快照看不到开关状态**，C4 只能保证页面完整，开关值要看截图。
3. **C6 的「有回复」判据是出现新文本**，分不清是回复还是别的 UI 变化。必须看 `C6-after-send.png` 确认。
4. **C7 会被时间戳、未读数干扰**，失败时先看截图再下结论。
5. 没有断网、旋转、深色模式、字号的自动用例，见下面手工清单。
6. 脚本没有在真机上跑过，第一次跑出现的 `FAIL` 里有一部分会是脚本自己的问题。

## 3. 手工清单（脚本测不到的）

执行时每项记：通过 / 失败 / 未执行，失败附截图和步骤。

### 3.1 陪伴主页与文字对话

| # | 场景 | 期望 |
|---|---|---|
| M1 | 底部「陪伴」标签 | 是主标签；「角色对话（新）」只在抽屉测试分组里 |
| M2 | 选角色（林澈 / 苏黛） | 开场白与角色卡一致；切换后旧角色历史仍可查 |
| M3 | 发长消息（500 字）、连发 3 条 | 不丢、不乱序；回合进行中再发会排队或插话，不报错 |
| M4 | 回复生成中点停止 | 不再追加；可以继续发 |
| M5 | 回复生成中返回再进 | 不重复、不丢（SSE 重连 + `Last-Event-ID`） |
| M6 | 回复失败后点重试 | 同一条消息重发，不产生重复气泡 |

### 3.2 语音（live 才有意义；注意服务端语音 worker 目前是占位大脑）

| # | 场景 | 期望 |
|---|---|---|
| M7 | 首次切到语音 | 先出解释框，再出系统麦克风授权；拒绝后给出可理解的提示 |
| M8 | 通话中：静音 / 免提 / 蓝牙耳机 | 音频路由正确 |
| M9 | 来电 / 别的 App 抢音频焦点 | 通话停止并提示，不崩 |

## 4. JVM 单测（不用手机，每次提交都能跑）

本轮新增，补的是原来没覆盖的客户端逻辑：

| 文件 | 内容 |
|---|---|
| `feature-companion/.../HttpCompanionApiTest.kt` | 鉴权头、未登录不发请求、各状态码的中文提示、5xx 正文不外露、非 JSON 不崩、ID 转义防路径注入、POST 空体、偏好 null 清空 |
| `app/.../agent/SseEventMappingTest.kt` | 18 种服务端事件的字段映射（17 个用例）、缺字段丢弃、坏 JSON 丢弃、未知字段忽略、SSE 解析器边界 |

**已在本机跑过：`HttpCompanionApiTest` 12 个、`SseEventMappingTest` 17 个，全部通过**（`:feature-companion:testDebugUnitTest`、`:app:testChatDebugUnitTest`，只跑了这两个类，没跑全量）。

这两个文件用假拦截器代替网络，所以**服务端没部署时它们照样能跑**——它们验证的是客户端自己。
仍然没有单测的：`AgentEventReconnector`（重连退避）、`LiveKitCompanionTransport`、各 Compose 页面。
