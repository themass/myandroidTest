## 1. 设计目标与依据

用户提的原话是这七条（2026-11-15）：

> 1）toolbar 应该跟 chat 一样，有抽屉和选角色
> 2）"文字""语音"这个开关一点意义都没有
> 3）陪伴不一定就是语音输出，最好加一个选择
> 4）内容展示区域可以抄袭一下 chat
> 5）等待 ai 返回的样式太丑，可以展示"对方正在输入…"
> 6）消息上面这个大框不知道是什么
> 7）豆包的"电话"通话效果

所以设计的第一原则不是「好看」，是 **「和对话页是一家人，但只加它没有的东西」**。
凡是 chat 已经解决的（气泡、时间戳、复制/删除/重新生成），一律用 `:chatkit`，不另造一套。

## 2. 聊天主页面

### 2.1 顶栏（对应问题 1）

```
[☰]  陪伴            [⌃/⌄]  [👤]  [✨]
 │      │              │      │     └─ 个性化页面：记忆、重要日子、她的主动性
 │      │              │      └─────── 角色选择
 │      │              └────────────── 展开/收起形象区
 │      └────────────────────────────── 标题
 └───────────────────────────────────── 抽屉（与对话页同一手势位置）
```

**一个修过的错误**：上一版「角色」用的是电话图标，而「个性化」用的是和「展开形象」一模一样的
向上箭头——用户只能靠猜。现在四个图标的语义各不相同，并且每个都有 `contentDescription`。

### 2.2 形象区（对应问题 6）

那个「占屏 42%、不知道是什么」的大框改成**默认可收起**的形象区，`avatarExpanded` 默认 `false`。

理由：形象是陪伴感的一部分，但它不该常驻抢占消息空间。用户打开页面想看的是**说了什么**，
不是看一张静止的图。展开是用户的主动选择，收起是默认。

### 2.3 消息区（对应问题 4）

直接用 `:chatkit` 的 `ChatMessageList`，`CompanionMessage` → `ChatItem` 映射。

附带得到的东西（不是为陪伴页单独做的）：气泡、Markdown、长按菜单、复制/删除/重新生成 footer。

**主动消息的打标**走 chatkit 的 `itemOverlay` 插槽——`ChatItem` 没有「谁先开口」这个语义，
硬塞进气泡会让主页面与对话页的气泡产生分叉。标签画在气泡**上方**，不占气泡内容。

### 2.4 「对方正在输入……」（对应问题 5）

三个点依次跳动，600ms 一个循环，每个点错开 160ms。

判定条件是 `awaitingReply`：最后一条是助手消息、内容为空。也就是**等待首字阶段**，
收到第一个 delta 就消失。这比显示一个空气泡准确——空气泡让人以为回复是空的。

### 2.5 输入区（对应问题 2、3）

```
[ 说点什么…                              ] [发送]
[🔊] 文字回答                        [📞 通话]
```

- **删掉了「文字 / 语音」分段按钮**。它切的是**传输路径**（进不进语音房间），
  用户看不出区别，是纯粹的实现细节泄漏到界面。
- 换成**语音输出开关**（`CompanionOutput { TEXT, VOICE }`）：她说的是文字，还是语音+文字。
- 通话按钮进全屏通话页。

## 3. 全屏通话页

### 3.1 配色

深夜靛蓝渐变 + 紫罗兰强调色：

| 用途 | 值 | 理由 |
|---|---|---|
| 渐变顶 | `#161F3D` | 能看出是蓝紫，不是灰 |
| 渐变中 | `#0B1122` | 大部分内容落在这层，压深保白字对比度 |
| 渐变底 | `#05060C` | 近黑但不纯黑 |
| 强调 | `#8B7CF6` | 冷紫；暖色（橙/粉）在长时间通话里会显得躁 |
| 静音态 | `#8590B0` | 去饱和青灰；语义是「冷下来了」，不是变红报警 |
| 挂断 | `#E5484D` | 整页唯一的高饱和暖色，只给挂断一个出口 |
| 重连 | `#F0B67F` | 琥珀；「可恢复的异常」，不是错误红 |

**为什么不用纯黑**：纯黑（`#000000`）在 OLED 上会让呼吸环失去参照——环和背景都是黑的，
光晕没有落点，整页像一块死屏。

### 3.2 动效

分两级，因为两者离视线的距离不同：

| 元素 | 时长 | 理由 |
|---|---|---|
| 波形 | 110ms | 在屏幕底部，离视线远，必须**跟手** |
| 呼吸环 | 280ms | 在头像外围、面积大，跟太紧会显得「抖」 |

波形条数是奇数，让中间一根正好落在中心线上。相位循环 1.6s——接近说话的语气节奏，
太快像噪点，太慢像卡住。

### 3.3 三个状态

- **说话态**：环随电平扩张、波形起伏、字幕末尾带光标
- **静音态**：环与波形降到青灰，顶部出现「已静音」药丸
- **字幕态**：压在画面底部，此时不画波形——一屏只保留一组运动元素

**一个刻意的反直觉决定**：静音时波形**不冻结**。它画的是**她的**声音，不是你的麦克风；
把自己静音画成她也不出声是错的。

## 4. 这一版没有成立的部分（重要）

必须写清楚，否则下一个人会以为这些是「已经做完的」：

| 项 | 现状 | 卡在哪 |
|---|---|---|
| 波形/呼吸环 | **静态**，`audioLevel` 恒为 `0f` | 没有把 LiveKit 音轨接到电平计算 |
| 静音按钮 | 空函数 | `LiveKitCompanionTransport` 没有 mute 方法 |
| 摄像头按钮 | 空函数 | 同上，没有相机轨 |
| 语音条 | **永远不显示**，`voiceSeconds` 恒为 `null` | 服务端推的是一条连续音轨，没有分句与时长边界 |
| 形象区展开 | 展开后是空白 | 设备上 `files/avatars` 为空，没有素材 |

换句话说：**布局、配色、动效常数都是按理由定的；但通话页的动效目前是骨架**。
它渲染得出来，只是不动。

## 5. 与「对话」页的关系（设计上的边界）

| | 对话页 | 陪伴页 |
|---|---|---|
| 传输 | `/v1` SSE | LiveKit 房间（文本走 data channel） |
| 历史 | 按会话 | **同一段**（服务端 `resolve_chat_session()` 保证一角色一段） |
| 角色 | 283 条目录 | 2 张陪伴卡 + 目录 |
| 独有 | 附件、多选、编辑、TTS | 形象、通话、主动性、待确认卡片 |

陪伴页**不读历史**这件事已经修了（见 `76da0fb2`）：之前关掉重开是空页，
而历史其实一直写在 `/v1` 里。

## 6. 如果要真正做完，缺什么

按依赖顺序：

1. **电平**：把 `LiveKitCompanionTransport` 订阅到的 agent 音轨做 RMS，喂给 `CallState.audioLevel`。
   这一条做完，波形和呼吸环立刻活。
2. **mute / camera**：transport 上加 `setMicEnabled`、`setCameraEnabled`。
3. **语音条**：服务端在事件里带分句与时长（`message.done` 里加 `segments[]`）。
   这是唯一必须改服务端的。
4. **形象素材**：`files/avatars` 要有内容；目前 `avatar-2d-design` 那条线在做。

前两项是纯客户端，加起来约 100 行。
