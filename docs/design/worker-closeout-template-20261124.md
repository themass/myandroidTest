# Worker 任务收口模板（2026-11-24）

用于让协调人判断一个已分派目标是否完成。目标内的功能、验证和证据都齐全才标 `PASS`；遇到外部条件阻塞标 `BLOCKED`，并保留 owner 与下一步。独立的新方向转为单独任务，不得用它们替代本目标的收口。

## 可复制任务卡

```markdown
### [任务编号] 任务名称
- Owner / session：
- 目标分支 / commit：
- 状态：PASS | FAIL | BLOCKED

**目标**
- 用户可观察的完成条件：

**范围**
- 本任务包含：
- 明确不包含：

**交付**
- 变更文件 / 文档 / 提交：
- 行为结果：

**验证**
- 命令或人工步骤：
- 实际结果（含退出码、通过/失败数或逐项判定）：
- 未执行的验证及原因：

**证据**
- 可复核路径、日志、attempt/job、设备/包版本、截图或录屏：
- 证据覆盖范围及局限：

**阻塞与目标内遗留**
- BLOCKED 项：责任人、具体依赖、下一动作、预计恢复条件：
- 目标内未完成项：

**独立后续**
- 只记录不改变本目标状态的新方向：
```

## 状态判定

- **PASS**：范围内每条验收条件都有新鲜证据；交付已在目标分支；没有未登记的目标内遗留。
- **FAIL**：验证已执行并证明至少一条目标条件不满足；记录失败证据和修复动作，不关闭任务。
- **BLOCKED**：无法执行的条件明确依赖设备、素材、凭证、产品决策或外部服务；记录当前已完成部分和解除阻塞所需动作，不把未验证写成通过。
- 不以 session 空闲、APK 已安装、代码已提交或某个单测通过单独推导整个任务 PASS。

## 填写示例：P0.5/P2 协议验收

- **目标**：验证协议行为：成功协商并上麦；引导静音不触发 t0/barge；真实远端音频后才开放 barge；实际可听期间允许打断。
- **范围**：只关闭协议与可听打断验收；不关闭首帧性能和服务端空回复。
- **状态**：PASS（协议项）。
- **验证/证据**：`docs/design/p05p2-proc-table-20261123.md` 记录了多轮同 attempt/job 的端/服务端配对，包含正式轮和截断样本；分别记录 `hello_ack`/`negotiated` 同 sid、静音期无 barge、真实首音频后 t0，以及可听窗中的 `speech_cancel`/TTS 截断证据。
- **目标外但仍开放**：`first_ms` 慢与 `said=''` 空回复按不同证据签名转交 F16/TOS 线，不改变已通过的协议结论。
- **证据限制**：此示例引用现有对账文档中的 worker/协调记录；新任务填写时仍需记录本次实际验证时间、设备/包版本和直接证据位置。
