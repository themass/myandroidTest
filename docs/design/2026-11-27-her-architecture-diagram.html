Her：App × 服务端架构分层图

实线 = 现在代码里真实存在的路径；虚线 = 设计草案（角色发布契约等）；粗青线 = 本机闭环（不出设备）。「特效测试」面板与相机手势汇入同一条 gesture 词表——单一事件总线是全图最关键的接缝。
已实现链路 草案 / 待接入 本机闭环（不上传）

高内聚：现在成立的接缝 ✓

  • feature 互不依赖：:feature-companion 不 import :feature-camera-fx，跨域内容由 :app 组合根注入，ModuleGraphTest 在测试里钉死。
  • 单一事件词表：服务端 cue、托盘、特效面板、相机手势全部汇入同一条 gesture → gestureSeq 流；特效层只认 StageEffect，不认识协议也不认识引擎。
  • 资产白名单：FxAssets / StickerAssetIds 是唯一注册点，未登记资产永远进不了渲染；面板选项从白名单派生（StageFxOptions），不存在第二份清单。
  • 引擎统一接口：新引擎 = Registry 加工厂 + 实现 DigitalHumanEngine；UI/ViewModel 不感知具体引擎。
  • 包安装校验：新 CharacterAssetPack 把「引擎类型 + 版本 + 逐文件哈希 + 暂存发布 + 失败保留旧版」做成引擎无关的契约。

可扩展性：已知缺口 ✗（图上红/虚线）

  • 包机制双轨：旧 AvatarPackStore（立绘/分层）与新 CharacterAssetPack 并存，尚未合并；引擎侧 AssetStore 的清单没固定哈希，下载不校验。
  • 角色↔引擎未贯通：进房默认仍是角色绑定的立绘；数字人引擎靠实验菜单手选，「目录返回引擎类型→自动选引擎」未实现。
  • 服务端 release 契约是草案：persona/voice/skills/包哈希/wardrobe 版本固定尚无 API；touch 上报还在 v1 黑洞。
  • 特效锚点是固定视口坐标：不跟随模型骨骼或舞台缩放；「Her 特效跟部位绑定」需要引擎侧提供真实锚点后才能升级。
  • 相机贴纸≠视频合成：贴纸只画在本机预览上，未合成进 LiveKit 发送的视频轨。
