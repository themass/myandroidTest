# 影视字幕方案：免费多语言字幕与译文

日期：2026-11-22 ｜ 状态：方案待拍板 ｜ 关联：`media-suite.md`「字幕」一节

## 0. 问题回到原句

> 我想要一个免费的、端上的字幕，支持多语言；在字幕之上再加翻译，把影视的语言翻译成用户指定的语言（只支持固定几种也可以）。

拆开是三件事：**字幕从哪来**（在线来源）、**字幕长什么样**（渲染，已就绪）、**多语言怎么解决**（翻译）。本文逐条给方案，并明确哪些是免费的、哪些有成本。

## 2. 免费的「在线字幕来源」：现实核查

| 途径 | 结论 |
|---|---|
| OpenSubtitles 官方 API | 2024 年起 API 转付费，免费额度基本收回。**不可作为免费依赖** |
| 「伪射手 / subhd」类解析器 | 灰色聚合站，随时挂、有版权与合规风险，不适合产品正式依赖 |
| 射手/subam 等站点直连 | 同上，且无 SLA |

**结论：市面上没有既免费又可靠的第三方字幕 API。我们的「免费」应该是：自建字幕库（人工/半自动导入）+ 自建免费翻译，零第三方 API 调用费。** 现有服务端接口就是字幕库的骨架，只差数据。

## 3. 方案 A（推荐）：字幕库 + 自托管翻译，批量离线

> 一句话：谁选了外语片，第一次有人要译文时服务器整篇翻一次、存起来，之后所有人都白嫖缓存。

### 链路

```
播放页字幕面板 →（已有）拉原语言字幕轨
              → 原语言 ≠ 目标语言？→ POST translate.json(videoId, targetLang)
                   ├─ 缓存命中：秒回整篇译文 cues
                   └─ 未命中：后台分批翻译入库，轮询/稍后再取
              →（已有）CaptionOverlay 按用户预设渲染，可选「原文+译文」双语
```

### 翻译引擎（免费的主体）

| 选项 | 成本 | 说明 |
|---|---|---|
| **LibreTranslate（Argos）自托管在 104** | 0 调用费，只有电 | 部署最简单（Docker/单进程），zh↔en 质量好，日韩西可用；CPU 即可 |
| Meta M2M100（int8 量化）自托管 | 0 调用费 | 100+ 语言、质量更稳，CPU 慢一档；量大再换 |
| 火山/百度 API（备胎） | 按字符付费 | zh↔ja 等方向质量最好；只在缓存未命中时触发，单部电影（≈3 万字符）成本以「分」计，可设开关 |

一部 120 分钟电影约 2–4 万字符；LibreTranslate CPU 单核约几千字/分钟，**整篇首翻分钟级完成**——对「点开一小时内肯定不重看同一片」的缓存策略完全够用。504 上跑无压力。

固定语言（先 5 种）：**zh / en / ja / ko / es**。

### 服务端落地（全部对齐现有约定，一个新表一个接口）

- 迁移 `sql/2026xxxx00_subtitle_translation.sql`：
  `vpn.subtitle_translation(id, videoId, langSource, langTarget, contentHash, cuesJson MEDIUMTEXT, engine, createTime)`
  `UNIQUE(videoId, langTarget, contentHash)` —— **contentHash 取原字幕正文 SHA-256**：换了字幕文件自动失效重翻，内容没变永远命中。
- `POST /api/video/subtitle/translate.json`（登录，`*.json` 老链路，JsonResult AES 正常走）：命中回 `{cues, engine}`；未命中要么同步翻完（短轨），要么回「翻译中」状态由 app 轮询（长轨）。
- 翻译过程：解析 SRT/VTT → 按 cue 文本分批（每批 ≤ 30 条或 ≤ 4KB，给引擎留余量）→ 调引擎 → 重新组装 `cuesJson`（`[{atMs, endMs, text, original}]`）→ 入库。任一批失败只重试该批。
- 解析/组装纯函数写单测（照 `PhotoSolveJsonSalvage` 风格），引擎藏在接口后面，LibreTranslate 和 M2M100 可换。

### app 端落地

1. 字幕面板加「翻译字幕」区：目标语言单选（5 种）+「双语显示」开关；选完即拉 translate.json，未就绪显示「翻译中，稍后可见」。
2. 拿到译文后走现有 `CaptionOverlay` 渲染（预设、样式、偏移全部复用）；双语时译文为主行、原文小字附行。
3. 译文按 `videoId+lang` 存内存即可，不占本地存储（服务端已有永久缓存）。

### 验收口径

- 导入一份日语 SRT，首个用户切中文：≤ 2 分钟内出整篇译文；第二个用户切中文：≤ 1 秒。
- 换一份字幕文件重新导入：旧译文不误用（contentHash 变了），重翻一次。
- 全程无第三方调用费。

## 4. 方案 B：实时 ASR + 翻译（给无字幕的片源，先不承诺）

链路：端上 PCM 采集 →（服务端 whisper 或端上 whisper.cpp）ASR → 翻译 → 叠字。

明确的拦路虎：
1. 现有 `realtime/` 流水线只接旧 ExoPlayer 的音频路；放映厅已切 `KernelHost`（IJK/Exo 双内核），**PCM 分支要从零接**。
2. ASR 质量：whisper.cpp 端上 small 对影视人声+背景音勉强，large 需要服务端 GPU。
3. 免费可自托管（whisper 本地跑），但工程量集中在 1，且质量不可控。

**定位：实验项，不进近期承诺。** 若要推进，第一步单独立项做 KernelHost 的 PCM tap（这本身对「语音输入到智能体」等场景也有复用价值）。
