# Her 形象包、相机与视觉效果设计

状态：设计提案；除文中特别指出的既有能力外，尚未实现或验证。目标是手机 App。

## 角色与资源

目录服务提供角色 ID、名称、介绍、缩略图及发布版本；发布版本引用角色包描述，包含引擎技术标识、包格式版本、版本号、大小、SHA-256、来源和兼容要求。客户端按技术标识查找引擎适配器，不认识或不兼容的技术显示不可用，不静默切换到其他角色。人设、TTS 与技能由发布版本引用，私有提示词和鉴权由服务端管理。

测试期内置资源与未来下载使用相同的安装入口：以可信目录提供的哈希验证归档，解压到应用私有固定目录的暂存区，限制路径、文件数量和解压大小，验证 manifest、所需文件及各文件哈希后原子激活；失败不替换当前可用版本。保留上一版本以供恢复，重启后检查已安装文件完整性。下载中、待安装、已就绪、损坏、更新和不兼容都应有明确状态。包内路径不可逃出包目录，服务端下载地址不应获得应用登录凭据。

包头通用，具体资源由技术适配器解释，例如 Live2D 的 model3 及其依赖、VRM 的模型文件。衣橱只从版本固定的 `wardrobe-spec.json` 读取槽位、候选和引擎绑定；模型未提供的部位不能伪装成可换装。房间入口须绑定角色及其发布版本，安装完成后通知界面刷新，再创建或恢复该角色的会话。角色列表、下载及房间之间的完整链路目前尚未接通。

现有 `AvatarPackStore` 已对立绘包强制校验归档哈希并检查解压；它现阶段不支持通用数字人模型包的完整契约，也不保证上个版本保留。`AssetStore` 有下载与暂存，但现有引擎清单未固定哈希，不应当成完整性保障。

## 手机界面和命令

角色列表展示封面、姓名、简介和资源状态；已就绪可进入房间，未下载可下载，失败可重试。房间保留人物为主的舞台和现有对话操作，衣橱从角色可用槽位展开。相机是本地预览小窗，默认左下，可拖动；权限拒绝时保留文字/语音对话。预览与发送视频是不同能力，发送前须另行接入并说明。

效果面板分「特效」「贴纸」两个类别和「Her」「我」两个目标；不可用的组合显示原因，不能用按钮暗示已经支持。统一命令需包含版本、命令 ID、目标、类别、资源 ID、动作（播放/停止）、可选锚点及参数；UI 和未来 agent 使用同一经验证的命令语义，服务端事件沿 `cmp.cue` 映射到独立叠加层。资源 ID、目标及参数由白名单校验，不允许服务端直接指定任意本地路径。重复事件按命令 ID 去重。相机贴纸依赖人脸跟踪，人物贴纸依赖具体引擎可用的锚点；固定视口坐标不能宣称绑定模型骨骼。

## 已有素材清单（静态代码盘点）

| 素材 | 现有实现 | 限制 |
|---|---|---|
| `fx_pat_head` 摸头爱心 | 角色舞台 Lottie；相机模块有副本 | 舞台锚点为固定视口坐标 |
| `fx_wave` 挥手光弧 | 角色舞台 Lottie；相机模块有副本 | 舞台锚点为固定视口坐标 |
| `fx_connected` 接通花瓣 | 角色舞台全屏 Lottie | 粒子关闭时不播放 |
| `fx_swipe` 滑动流光 | 角色舞台 Lottie；相机模块有副本 | 事件反馈而非持久贴纸 |

相机实验模块具备人脸顶部定位的 Lottie 贴纸和本地关键点分析；目前不能据此认为已实现所有目标与类别组合，也不能认为效果已合成进通话视频。效果实验室另有 Rive、GLES3 粒子、AGSL 和 Three.js 方案，属于实验能力；Rive 示例素材许可尚需核实，AGSL 需 API 33 以上。具体跟踪表现和设备性能仍需真机验证。
