# 对话问题与图集设计方案（草案，待确认）

## 1. 文字消息大量失败：是 mock 还是真失败？

**结论：是真实失败，不是 mock。** 对话的文字和附件都走真实接口（`ChatRepositoryImpl.streamChat` 和 `sendAttachment`）。mock 只在拍照解题（`PhotoSolveRepository`）里。

我在手机上抓到的失败原因：
- **已修**：删除会话后当前会话 id 没清掉，服务端返回 `errno 11003 会话不存在或无权访问`，之后所有发送都失败（`212f012d`）。
- **未查清**：其它偶发失败。我加了日志（`5517f8a0`，失败时打出 `stream reply failed` 和异常），下次出现时可以直接看到原因。

**重试按钮只剩最后一条的问题**（代码已定位）：
- `fallbackReloadMessages()` 重新加载历史时，只恢复「最后一条失败的用户消息」的失败状态（`failedText` 只取最后一条）。
- 更早的失败消息，如果已经拿到服务端 id，就变成服务端消息，`delivery` 默认是「已发送」，重试按钮消失。
- 所以「后面又来一个失败」时，前面的重试按钮会丢。

**设计**：
- 失败状态按**本地消息 key** 保存（不靠文字匹配，也不靠「最后一条」）。重新加载时，按 key 或 `clientMsgId` 对齐，失败的继续标为失败。
- 失败消息的 id 替换规则统一：只有服务端确认成功才换 id；失败的保留本地 id 和失败标记。
- 每条失败的用户消息都保留重试按钮，不限于最后一条。

## 2. 消息顺序乱：后发的消息跑到先发的图片前面

**根因（已定位）**：`fallbackReloadMessages()` 的结果是 `merged + localOnly`。`localOnly` 是本地还没同步到服务端的用户消息（比如刚发的图片），它被追加在服务端历史的**末尾**，而服务端历史里已经有更晚的消息，所以顺序错乱。

**设计**：
- 所有消息统一按一个时间轴排序：服务端消息用 `createdAtMillis`（或服务端时间戳），本地消息用发送时间。合并后统一 `sortedBy`，不再 `merged + localOnly`。
- 本地未同步的消息用它的发送时间插入正确位置，而不是追加。
- 验证：先发图片（慢）→ 再发文字，列表顺序必须是图片在前。

## 4. 长按图片菜单没了

**代码事实**：长按链路还在（`ImageGrid` → `onAttachmentLongPress` → 附件菜单），`actionsFor(Image)` 总是返回「下载、复制图片、分享、查看路径」。我在手机上测过：刚发的多图长按能弹出菜单，并且复制、下载、分享都能用（截图见 `ours_a2_*.png`）。

**所以问题很可能在「重新加载之后」**：
- 服务端历史接口不返回附件（代码注释里写着「附件不在对话历史接口里」），附件气泡只存在于本地缓存。
- 重新加载或重启后，如果附件消息的本地缓存没有被正确读回，图片就不显示，长按自然也没有了。

**需要你确认的复现步骤**：是刚发完就长按没反应？还是退出 app 重进后，图片消失或者长按没反应？我需要知道是哪一种，才能定位。
