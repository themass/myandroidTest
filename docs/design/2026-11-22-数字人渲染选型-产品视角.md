# 数字人渲染选型 · 产品视角

日期：2026-11-22 · 状态：分析/建议，待产品拍板
问题原样：① 现有几个数字人方案哪个能当产品用；② 未来扩角色、允许用户传照片生成 HER；③ HER 要支持点击、拖动、换装、吃饭这类端侧 action；④ 可以换更合适的方案（Spine、3ds Max、three.js 都在范围内）。

事实标注约定：**【实测】**= 本仓库代码/真机验证过；**【调研】**= 此前会话带来源 URL 的记录（`docs/avatar-2d-design.md`、`docs/her-research/`，核对日期 2026-11-11~17）；**【推断】**= 我的判断；**【新领域】**= 此前调研明确未覆盖。

---

## 0. 结论先行

**四个现有引擎，今天能当产品用的只有一个（Simple 分层立绘），而且它恰好是互动能力最完整的那个。**

| 引擎 | 现在能用？ | 产品级判断 |
|---|---|---|
| Simple 分层立绘 | ✅ 唯一开箱可用 | 零成本、零授权、点击已通；上限是"剪纸感"，撑不起换装商城 |
| DUIX 真人克隆 | ⚠️ 能跑不能玩 | 实时真人在端侧渲染【实测】，但动作表空【实测】、背景烤死、无换装/拖动可能、1000MAU 后收费+强制水印 —— 它是"会说话的视频窗口"，不是"可交互的 HER" |
| Live2D | ⚠️ 技术通、法务不通 | 口型/视线/摆头都有【实测】，但无自有模型、"avatar" 正是其 Expandable Application 条款的点名词【调研】，书面确认前不能上生产 |
| TaoAvatar | ❌ 不可用 | A2BS 未接线（能力位只有 STATE）、libtaoavatar.so 未打包、麒麟 GPU 必崩【实测】——纯 lab 展品 |

**产品需求的本质**：点击/拖动/换装/吃饭/选角色/照片生成——这六件事全部落在"**形象必须是可操作资产**（骨骼、皮肤、动画时间轴、命中区）"这一条轴上。DUIX 的写实恰恰是不可操作的：换装要重训模型、吃饭要素材里有这段视频、拖动根本没有参数可驱动。**写实和高交互度在同一个引擎上互斥，这是路线属性，不是实现不到位。**

**推荐格局（三条线，不是选一个）**：

1. **主线 · Spine 骨骼 2D**（6–9 个月窗口）：换装=skin 字典（教科书场景）、吃饭=动画时间轴+道具 attachment、拖动=骨骼 IK/物理约束、点击=attachment 命中区、扩角色=外包管线成熟、一套资产跨 Android/Web/iOS。2026-11-11 的文档把 Spine 押后是因为当时产品前提"不做换装"——**今天你明确要换装了，前提反转，结论跟着反转**。成本：$379 编辑器（含运行时、无 MAU 抽成）+ 每角色外包约 ¥0.5–2 万【调研+推断】。
2. **写实线 · 服务端渲染，不做端侧写实**：端侧写实的天花板就是 DUIX（交互为零）；云厂商报价全线超纲（腾讯 ¥80 万/年/APP、火山 ¥42 万/年/路并发、百度 ¥3.6 万/20 台、阿里停售【调研】）。唯一经济上说得通的写实路线是**自建服务端 talking-head 推理 + 现有 LiveKit 推流**，定位"高级订阅·真人 HER"SKU。OSS 候选（heygem / MuseTalk / LivePortrait 等）**此前调研完全没查过，含许可证在内都是【新领域】**，先做 spike 再说。
3. **照片→数字人 · 做"照片→风格化立绘"，不做"照片→真人克隆"（第一阶段）**：上传几张照片 → 图像模型生成风格化立绘 → 自动分层（分割+补全遮挡区）→ 进 Simple/Spine 资产管线。资产仍是我们的，可审核、可商用、无肖像权雷区。真人换脸 clone 是全场监管最重的功能（下面 §5），等产品验证+法务就位再说。

**不建议现在做的**：3D 运行时（Unity UaaL 全屏限制 / Godot 增量 76MB / VRM 逐模型商用授权雷区【调研】）、用户声音克隆（北京互联网法院已判赔 25 万【调研】）、任何"按 APP 买断"的云厂商接入。3ds Max 是离线建模工具不是运行时——它属于"做 3D 资产"的世界，先不进门；three.js 属于 Web 版——**如果哪天真要走 3D，先做 Web 版用 three.js+VRM 验证，别在 Android 原生里嵌**。

## 1. 产品需求解码：HER 的功能清单落在哪条轴上

| 需求 | 需要的底层能力 | Simple | Live2D | DUIX | Tao |
|---|---|---|---|---|---|
| 点击有反应 | 命中区 + 本地反馈 | ✅ 已上线【实测】 | ✅ 同链路可复用 | ⚠️ 只能发 touch 给 agent，画面无反馈 | ❌ |
| 手指拖动（她转头/被凑近） | 可驱动参数（IK/约束/gaze） | ⚠️ 只能整层平移 | ✅ GAZE 已有【实测】，加头骨约束即可 | ❌ 无可驱动参数 | ❌ |
| 换装 | 运行时皮肤/零件切换 | ❌（整图重画） | ⚠️ part 显隐是 hack【调研】 | ❌ 素材级不可能 | ❌ |
| 吃饭（内容型动作） | 动画时间轴 + 道具 | ⚠️ 序列帧组合爆炸【调研】 | ⚠️ 要重画全部 mesh，很贵 | ❌ 动作表空【实测】 | ❌ |
| 扩展多角色 | 外包管线 + 每角色边际成本 | 低但上限低 | 中（模型 ¥0.5–3 万/个） | 高（每个都要真人拍摄+训练）| — |
| 用户照片生成 | 资产自动化管线 | ✅ 立绘分层是唯一可行入口 | 同左（转 Spine/Live2D 模板） | 即真人克隆（监管重） | — |

一句话：**六项需求里五项指向"2D 骨骼资产运行时"，一项（照片生成）指向"资产生成管线"，零项指向"真人视频"**。这就是选型的主轴。

## 2. 现有四引擎实证盘点

**Simple 分层立绘（自研）**——能力位 `STATE/EMOTION/MOUTH/TOUCH_TAP`【实测: SimpleAvatarRenderer.kt】。呼吸、眨眼、嘴型、情绪、点击脉冲全通；`AvatarStageTransform` 双指缩放/拖动、陀螺视差、主题色板都已挂在它身上。上限（`docs/avatar-2d-design.md` §0 已钉死）：剪纸感、头发不随头摆、转头无弧面变化。它永远该保留——**免费兜底 + 低端机降级层**，这是降级梯子（P4）的一部分【实测: DegradeController】。

**DUIX（硅基智能）**——真机 Oliver 实时渲染出画面、口型由远端 PCM 驱动【实测】。但产品级致命伤四条：
1. `motionRegions` 空表【实测: duix-motion-scan，21 个 id 全扫零命中】——「转身/挥手」要带动作区间的素材，客户端修不了；
2. 人物背景烤进模型素材【实测】——我们的主题色板对它无效，"HER 的房间"不可定制；
3. 无换装/拖动概念——它是端到端视频合成，没有任何暴露给客户端的可操作对象；
4. 商务：开源版强制 "Powered by Duix.com" 水印，**>1000 MAU 需要付费授权**【调研】；上游推荐骁龙 8Gen2+8GB【调研】，连发音频 clip <4s 会 native crash【实测】。
定位建议：保留为 lab 里的"写实试验田"，**停止在它身上继续投交互功能**（动作轮盘的置灰行就是这条线的墓碑：不是不做，是素材不给做）。

**Live2D**——MOUTH/EMOTION/GAZE/STATE + 说话摆头【实测】。质量是二次元立绘天花板。三个前置未清：无自有模型（ATRI 无公开 URL【实测: AssetManifest 故意留空】）、Expandable Application 条款把 "avatar" 写进了例子（若命中则无小规模豁免、分成 20% 或 ¥300/激活【调研】）——固定官方模型+不开放 UGC 的形态**可能**不构成 expandable，但这是【推断】，动工前必须拿到 Live2D 书面确认【调研共识】；换装在它这里是 hack。定位建议：将来"二次元外观"支线，等书面确认+自有模型。

**TaoAvatar（阿里 MNN）**——能力位仅 `STATE`，A2BS 未接线，`libtaoavatar.so` 未打包，≥8GB 内存门 + 麒麟 GPU 必崩【实测】。除非阿里开源关键件且我们重编 JNI，否则当它不存在。

**架构资产（比任何引擎都值钱的东西）**：`AvatarCommand`（MOUTH/EMOTION/GAZE/STATE/GESTURE）+ `AvatarCapability`（含已预留的 `TOUCH_DRAG/TOUCH_TAP`）+ CueCompiler（服务端结构化 cue，SERVER_CAPS 已开 gesture/gaze【实测】）+ 引擎适配器模式。**协议层完全不认识任何具体渲染引擎**——这正是 Grok Companions 关停 3D 形象层而人格存活留下的教训（人格与渲染必须解耦【调研】）的落地。换任何新引擎（Spine/服务端流）只是多写一个 adapter，这条护城河今天就存在。

## 3. 三条技术路线细案

### 路线 A · 2D 骨骼资产运行时（主线）

- **Spine**：换装=skin 字典运行时合并（唯一把换装做成数据结构而不是工程 hack 的 2D 方案【调研】）；吃饭=动画时间轴（进食循环 + 餐具 attachment 开关）；拖动=IK/transform 约束 + 物理（头发、发梢跟随手指）；点击=骨骼/attachment 命中。实测体积 2.54MB JVM、零 .so【调研】；$379 编辑器含运行时、无版税无 MAU、>50 万美元营收才触发 Enterprise（$2,499+席位）【调研】。美术外包生态最成熟（日系手游标配），"HER 骨骼+3 套衣服+进食+待机"这样的角色单件约 ¥0.5–2 万【推断】。
- **Live2D**：见 §2，二次元外观支线。
- **DragonBones**：MIT + 现成 Android Compose 包装（含 tap-slot 命中）【调研】，但无 Maven、2025-07 起停更【调研】——只用来做 spike 验证，不做产品依托。
- **Rive**（备选，不作主线）：编辑器交互最好，但定价是按席位订阅（$9/$32/$120 每席/月，Free 层带强制开屏水印）【调研】——外包协作模式下每多一个动画师多一份月费，商业模型上不如 Spine 一次性买断契合。
- **自研分层进化（Simple+）**：`docs/avatar-2d-design.md` §1.9 的六件套（瞳孔层视线、眉毛层、随机微动作调度…）是把免费线做到上限的路，两周工作量【调研】，与上 Spine 不冲突——它同时是 Spine 缺席期/低端机期的观感兜底。

**A 路线的代价要明说**：2D 再怎么做不到"真人"；吃的是美术管线和外包管理的饭，工程解决不了"画得不行"。

### 路线 B · 写实线 = 服务端渲染（不做端侧）

端侧写实（DUIX）已判死；云厂商按路/按设备计价全部超纲【调研，报价见 §0】。剩下一条路：**自建服务端 talking-head 推理 + LiveKit 推流**——TTS PCM 进、合成视频流出，接在我们现成的 LiveKit 媒体面上，Android 端只是多订阅一条视频轨（工程一天级【推断】）。

候选 OSS：heygem（腾讯）、MuseTalk、EchoMimic、LivePortrait、SadTalker——**这些此前调研一律没查过：质量、实时率、显存、尤其许可证（研究代码常见 non-commercial 条款）全部是【新领域】**，任何结论前要先做一轮 spike+许可证普查【推断】。

成本量级【推断，必须实测】：实时单流约需 A10/L4 级推理卡一张，¥6–15/卡时 → 单并发月成本约 ¥4,000–10,000 → 这决定了写实 HER 只能是付费订阅 SKU，不能进免费池。合规：写实数字人视频触发《人工智能生成合成内容标识办法》显式+隐式标识（应用商店上架要查）【调研】，详见 §5。

### 路线 C · 3D（不进门，留门牌）

互动自由度确实最高（绕房间走、拥抱、镜头运镜、真·空间音频），代价是资产管线重一个数量级：3ds Max 建模→绑骨→动画→引擎，外包单价 3–10 倍于 2D【推断】。落地侧全有硬伤【调研】：Unity UaaL 只能全屏单实例（嵌不进聊天页）、Godot arm64 增量 69–76MB、VRM 模型逐件授权且商用默认禁止（`commercialUsage` 默认 personalNonProfit）。
留门牌的方式：three.js + VRM 做**Web 版**的"3D HER"预览/试玩页——浏览器里验证 3D 的陪伴感是否真的比 2D 强，再决定要不要付 3D 资产管线的钱。你说"3djs 都可以"——对，但它是 Web 的钥匙，不是 Android 原生的。

## 4. 用户照片 → 数字人（生成线）

分三段，按风险从低到高：

**① 照片 → 风格化立绘资产（先做这个）**：用户传 3–5 张照片 → 图像模型生成风格化立绘（即梦/SD 微调均可）→ 自动分层（分割 + 遮挡区补全）→ 套 Simple/Spine 模板 → 获得"会呼吸眨眼的卡通自己"。
- 商业上：这是陪伴产品验证过的增长钩子（捏脸/照片头像），且**生成的是我们美术规范内的资产**，可审核、可商用、可跨引擎复用；
- 技术上难在"分层+遮挡补全"的自动化率，人工兜底比例决定毛利——一周 spike 能量出来【推断】；
- 审核：用户可能上传明星/他人照片 → 生成物走"卡通化"本身即是减害（不构成深度合成意义上的真人面孔【推断】），但仍需内容审核位（复用图片通道的合规链路）。

**② 照片 → 写实数字人（服务端）**：技术上=路线 B 的管线 + 用户上传素材训练/推理。触发第 14 条"被编辑人单独同意"——**只能对本人**：需要活体比对（上传人脸与账号实名一致性），法务成本非线性【调研+推断】。放产品验证之后。

**③ 照片+声音 → 完整 HER 克隆**：肖像权+声音权双雷区，北京互联网法院 AI 声音案判赔 25 万、"录音许可≠AI 训练许可"【调研】。Part-K 的既有结论我同意：MVP 阶段不做。

## 5. 合规税表（选型的隐性定价，别在商店上架那天才看）

| 义务 | 触发条件 | 对路线的影响 |
|---|---|---|
| 《拟人化互动服务管理暂行办法》(2026-07-15 施行)：AI 身份标识、2 小时提醒、未成年人不得虚拟伴侣 | **本产品必然在内**【调研】 | 与渲染路线无关，任何线都要做；可设计成仪式感（"她有点困了"） |
| 《生成合成内容标识办法》(2025-09-01)+GB 45438：显式+隐式标识，商店上架核验 | 生成合成**视频/音频/虚拟场景** | 写实视频流（路线 B）全中；风格化 2D 骨骼渲染**大概率不构成**"生成合成视频"【推断，需法务确认】 |
| 深度合成规定 第14/15条：人脸编辑需被编辑人单独同意+安全评估 | 上传**他人/本人真人面孔**做换脸 | 照片生成线的①卡通化避开；②③直面 |
| 民法典 1019/1023 + AI 声音案 | 真人肖像/声音克隆 | ②③的长期风险定价 |

**选型含义【推断】**：风格化渲染（路线 A/C）的合规税 ≈ 平台级通用义务；写实渲染（路线 B）+真人上传（照片线②③）的合规税 = 安全评估+算法备案+同意验证+标识核验全家桶。**写实每多一分真实，法务成本指数加一。这也是"主线 2D、写实只卖订阅"的第二个理由。**

## 6. 天马行空区（产品玩法，先记下来）

- **换装商城 = 陪伴产品的正循环变现**：skin 即 SKU。单品（一顶帽子）→ 套装 → 场景包（"共进晚餐"= 餐厅背景层 + 进食动作 + 餐具 attachment + 灯光主题），场景包客单价天然高于单品。我们的主题色板系统（已完成）正好是"场景包"的光照半件。
- **吃饭/摸头/凑近 = 动作卡经济**：进食、依偎、递水这类"生活动作"按卡售卖或订阅解锁；长按动作轮盘已经是这个商店的货架原型。
- **"HER 就是你" 捏脸 = 订阅权益**：照片→立绘生成放订阅里，生成次数即成本闸；用户分享自己的卡通 HER 即免费获客。
- **1 人格 : N 形象 : M 音色**（brainstorm L2 的数据模型）：同一 HER 在免费线是立绘、高级订阅是服务端写实、将来 Web 是 3D——人格记忆与声音不变，形象只是皮肤。引擎适配器模式已经让这个"形象商城"成为纯数据工作。
- **这条路有人走通过（先例背书）**：Open-LLM-VTuber 的「LLM 情绪标签 → 表情映射」与我们的 CueCompiler 完全同构；AIRI 在同人圈把 Live2D 与 VRM 双渲染器挂在同一人格上跑通——"换渲染器不换人格"不是我们的发明，是已被验证的行业做法【调研】。
- **Web 版当 3D 与 UGC 的试验田**：three.js 做 3D 试玩、浏览器做捏脸工坊，验证完数据反哺 Android 原生决策。
- **低端机 = 2D 立绘 + 空间音频**：降级梯子已经把"换引擎不换人格"做成运行时，写实机与立绘机看到的是同一个她。

## 7. 落地节奏与总账

| 时间 | 动作 | 花什么 |
|---|---|---|
| 现在起 2 周 | Simple+ 六件套（瞳孔/眉毛/微动作）；DUIX 定位为 lab 展品，交互投入冻结 | 工程内部 |

**每新增一个角色的边际成本【推断】**：Spine ≈ ¥0.5–2 万（含首批 3 衣）；Live2D ≈ ¥0.5–3 万+许可前提；DUIX ≈ 真人拍摄+训练，且动作/换装/背景永远缺勤。**扩展更多数字人供挑选这个目标本身，就把票投给了 Spine。**

## 8. 需要产品拍板的五个问题

1. 主线审美定调：二次元立绘、还是"半写实厚涂 2.5D"？（决定外包画风与 Live2D 支线要不要谈）
2. "真人 HER"是必须有的 SKU 吗？要 → 接受 GPU 成本+标识合规，走服务端流；不要 → DUIX 冻结在 lab。
3. 照片捏人放 MVP 还是验证后？（增长钩子 vs 审核+同意成本）
4. 美术外包预算池（角色管线的主成本项，工程侧一次 $379 之后基本没有第三方费用）。
5. Web 版排期——它决定 three.js/3D 试验田和捏脸工坊哪天能开。
