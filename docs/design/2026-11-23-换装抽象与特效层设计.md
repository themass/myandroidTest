# 换装抽象架构 + Lottie/Rive 特效层设计(2026-11-23)

> 用户拍板:按队列①内衣换装管线→②Live2D 条款→③课程页→④Lottie FX→⑤Spine 推进,
> 「一定要注意抽象设计,换装换头饰是非常典型的设计模式」;Spine 只作技术测试,许可先不管。

## 一、换装 = 槽位/变体模式(引擎无关的单一抽象)

换装、换头饰、换鞋、换手持,本质是同一个经典模式:**Slot(槽位)× Variant(变体)× 引擎绑定**。
我们现有实现里这个模式已经被证明可用(ATRI 四轴 180 组合),但被写死成 Kotlin 枚举 +
生成器字典两处,加一根轴要改 6 个点——这次把它收成单一事实源。

### 概念(引擎无关)

```
WardrobeSlot   槽位:  id(underwear/top/shoes/hair/…) · 显示名 · 触摸分区 · 变体列表(单选互斥)
Variant        变体:  token(全局唯一,喂命名) · 显示名 · status(active|pending-param|pending-art)
                     · binding(引擎各自的开关机制,见下表)
WardrobeState  状态:  Map<slotId, variantToken>   (每槽单值;空 token=裸态)
应用层 API     step(region) 分区循环 · advanceWardrobe(slotId) 托盘推进 · rows() 托盘渲染
               —— DigitalHumanEngine 已有 wardrobeRows()/advanceWardrobe(),UI(AvatarActionTray)
               本来就是引擎无关的,抽象收的是资产与状态层。
```

### 各引擎的 binding(同一抽象,不同落地)

| 引擎 | Variant 的 binding | 加新素材的真实成本 | 现状 |
|---|---|---|---|
| **Live2D** | exp3 参数组 `{(Id,Value)}`,组合表情笛卡尔积 | moc3 里**必须已有**该 ArtMesh+参数;新素材=Cubism 编辑器重制 moc3(exp3 造不出新 ArtMesh) | 主线,4 轴已上线 |
| **Spine** | skin 名;运行时 `Skin.addSkin` 合成(spike 已证) | 编辑器产 skin 素材;runtime MIT 免费 | 测试线,许可暂不计 |
| **VRM** | 命名网格节点显隐 / 材质替换(three-vrm node visibility) | 建模工具产 VRM 变体 | 试验田 |
| **Simple** | 分层 drawable 换图层 | PNG 分层素材 | 已上线兜底 |

**抽象纪律**:命名、循环、托盘、分区映射只写一次(Kotlin);引擎差异全被 binding 吸收;
新增槽位 = 改一份 spec,不改状态机代码。

### 单一事实源:wardrobe-spec.json(本次落地)

`scripts/dh-lab/live2d-lab-assets/wardrobe-spec.json` 声明全部槽位/变体/参数绑定/验证出处。
- 生成器 `gen-expressions.py` 从它生成 exp3 与 model3 注册表(不再自带字典)。
- Kotlin 钉桩测试读同一份 spec:枚举机器 ≡ spec ≡ 180 资产 ≡ model3 注册表,四处同源防漂移。
- `status != active` 的槽位不进命名空间、不生成资产(内衣/头饰就是这种声明占位)。
- 数值纪律不变:只允许上游同款 moc3 已验证 (Id,Value),spec 里带 `verifiedFrom`。

### 内衣裤换装管线(队列①)的真实形态

Live2D 换装是**切换 moc3 里预画的 ArtMesh**,exp3 只能开关已有参数——所以内衣轴卡在素材不在代码:

1. **代码侧(本次+随后)**:spec 声明 `underwear` 槽 + `hair` 槽(status=pending-param);
   命名空间预留 token(`underwear-lace` 等);Kotlin 待槽位转 active 时只加 binding。
2. **素材侧(美术任务书,已含在 spec 注释)**:在 ATRI moc3 上重制——
   - 基线裸层(去外衣)+ 内衣若干套,每套一个 Opacity 参数,命名约定 `ParamWear_<variant>`;
   - 头饰同理(hdj Param23-30 上游存在但**无已验证值**,需先在编辑器里逐个人工验证显隐正确);
   - 「原始去衣 + 胸部增大」= 同一张 moc3 改版的基线改动,**一次重制 ATRI-v2 base**,
     重制后 spec 换 verifiedFrom 基线,全部槽位重新验证。
3. **验收**:槽位转 active → 生成器重跑 → 真机分区循环日志 + 截图(与现有钉桩同一回路)。

## 二、Lottie + Rive 特效层计划(队列④展开)

两者都 Apache/MIT、都有官方 Android runtime,补的是 Live2D 层**不擅长**的:矢量过场、
状态机小动画、全屏礼物特效。全部叠加在现有舞台层上,**不改原有 UI**。

| 优先级 | 场景 | 引擎 | 具体做法 |
|---|---|---|---|
| P0 | 礼物/弹幕全屏特效 | **Lottie**(lottie-compose 6.7.1) | 服务端 `cmp.cue` 协议已就位;礼物→Lottie 动画,KeyPath COLOR 换品牌色,progress scrub 控时长;素材社区 AE 模板可直接产 |
| P1 | 头像四态小动画 | **Rive**(rive-android MIT) | 待机/倾听/思考/说话 状态机,文件 KB 级,通话页头像区;一个 state machine input 接 TTS 播放态 |
| P2 | 换装过场 | **Lottie** | 补 Live2D 0.2s exp3 切换的视觉空档:闪光/布料飘动叠层,换装落定即消失 |
| P3 | 页面转场(含水墨意向) | Lottie | 纸纹+墨点序列帧做转场;真墨痕 shader 不做(成本不成比例) |

纪律:全部走现有 `reducedMotion` 开关(DigitalHumanLabHost.kt:132 等已埋);Lottie 合成
composition 常驻内存要按页释放;Rive 状态机文件入 assets 带钉桩测试(与 exp3 同一纪律)。
