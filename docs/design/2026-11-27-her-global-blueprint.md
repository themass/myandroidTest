## 1. 愿景与边界

面向世界各地不同文化、语言、身体与生活情境的人，提供一个**可选择、可理解、可控制、持续相处**的 AI 伙伴：它能对话、倾听、记住经允许的事情，以自然声音与用户选择的形象交流，并随用户需要参与日常生活。Her 是产品愿景和名称，不预设伙伴必须是女性、恋人、真人外貌或某一种文化；用户可以选择角色的称呼、表达、声音和关系边界。

- **长期体验**：可靠对话和记忆、自然语音与打断、可信的角色个性、可以换装和变化的场景、创作者供给与安全的跨端体验。
- **优先次序**：先让一个有授权、高质量角色在真实会话中可靠工作，再扩展可控记忆、个性化、产线和更多市场；不以角色数量、动效数量或最长使用时间替代体验。
- **尊重自主**：明确 AI 身份；记忆与主动互动可见可关；不诱导情感依赖、排他或付费换亲密；危机场景提供适当帮助而不声称医疗能力。
- **平等可及**：支持不同语言、性别表达、无障碍和低端网络设备；不对不同市场声称同时上线，按语言质量、服务覆盖及当地规则分批。
- **质量红线**：目标视觉不低于用户给出的 Live2D 参考；浏览器点粒子和简单模型只证明技术方向，不代表最终美术验收。

## 2. 用户旅程与产品设计

| 旅程 | 用户可做的事 | 系统反馈与失败状态 | 首发边界 |
|---|---|---|---|
| 发现与选择 | 了解 AI 身份、选择角色或静态体验、听声音预览 | 标注语言、设备能力、隐私和实际可用资源；加载失败可重试/更换 | 一个完整原创授权角色，保留后续角色目录接口 |
| 第一次相处 | 输入文字或授权麦克风说话；设昵称和语言 | 可见连接/聆听/回应状态、字幕、静音与退出；弱网降级文字 | 真实服务全链路；模拟结果明确标识 |
| 长期相处 | 自愿开启记忆，查看、更正、删除或要求不再提及 | 展示来源、时间及推断标记；删除状态可查；不把推测当事实 | 可控的最小记忆闭环，不默认收集敏感信息 |
| 个性化 | 调整声音、表情、衣橱、场景和动作强度 | 预览、确认、撤销与恢复；缺失/冲突项解释；资源不可用不破坏旧选择 | 只展示真实模型上已验证的选项 |
| 相机与共享 | 可选择开启本地摄像头贴纸，单独选择是否与对端共享 | 本地与发送状态清楚、可关闭，拒绝授权仍可聊天；不静默推流 | 首先验证本地效果；视频发送另做独立端到端验收 |
| 创作与分享 | 授权后上传自己的素材，创建角色草稿；预览并决定私有/发布 | 显示任务进度、人工步骤、使用权及失败原因；可撤销/下架/投诉 | 先内部工坊和授权资产；公共 UGC 在治理能力就绪后开放 |
| 退出与迁移 | 关闭主动互动、导出或删除记忆和账户 | 说明即时影响、异步删除进度与备份期限 | 定义并演练端到端删除，而非仅隐藏 UI |

声音馆保留既有**全部七项**已确认范围：①完播自动接下一首；②单曲循环、列表循环、顺序、随机四种播放模式；③0.25–3 倍速及持久化；④前台播放服务与通知控制；⑤接入既有 SOUND 本地收藏链路；⑥遵循既有用户设置的 Wi-Fi／非 Wi-Fi 播放提示；⑦歌词／实时字幕。历史方案中的字幕路径是对曲目音频进行实时 ASR，并非已确认存在 LRC 字段；实际能力、权限和数据流需按当时版本核验。七项逐项核对当前分支实现、并线测试和真机证据，历史验收记录不自动等于当前 PASS，也不得自行缩项。

角色陪伴、衣橱、场景与声音馆的共享资产通过统一清单互相引用，不重复维护作品事实。

### 体验规则

- 角色有稳定身份和人格版本，关系与用户实例绑定，更新外观或模型不重置用户记忆；模型升级先评测人格与记忆回归，可回滚。
- 主动问候需用户主动开启；本地时区免打扰、频率上限、连续未响应降频、一键停用，规则在服务端执行。无依据时不虚构统一最佳频率，先小范围验证。
- 实时语音支持可见的连接、听、想、说、被打断、恢复与退出；每个 turn 有取消和过期处理，旧回复不能覆盖新 turn。
- 尊重多种关系设定；敏感年龄和地域场景按实际适用规则限制。各地法规和商店要求必须在上线前核验，历史研究材料不能代替法律意见。
- 字幕、字体缩放、屏幕阅读、色彩对比、降低动态效果、静态或文字降级是基础能力；不同文化的翻译和角色语气需要当地人员评审。

## 3. 技术全景与已有基础

```text
用户 Android / Web / 后续客户端
  ├─ 文本、字幕、语音、摄像头与权限控制
  ├─ Character runtime（Live2D / Spine / VRM 等适配器）
  ├─ 统一 wardrobe-spec → 已验证的引擎绑定
  ├─ cmp.cue → 事件映射 → 独立舞台特效层
  └─ 可选 camera 合成 → 明确授权后视频轨 → 对端
             │ API / 事件 / RTC
             ▼
产品控制面：账号权限、角色目录、用户实例、设置、订阅、地域策略
会话面：连接 / turn / STT → 对话与记忆 → TTS / cue / 打断
内容面：项目与授权 → 工作流 → 工具和人工 → QA → 版本 → 审批发布
基础设施：持久任务、对象存储、监控、审计、配置、发布与回滚
```

**已见代码或记录，不等于上线验收**：Android 有 `DigitalHumanEngine` 抽象、Live2D 引擎、Spine WebView 适配器、VRM/TalkingHead 实验，Lottie 叠加与 `cmp.cue` 映射；CameraX + MediaPipe 为 debug 实验；LiveKit Android 当前工作树依赖 2.29.0。浏览器机器人 A/B 和 VRM 天气样件可用作早期证据，但真实设备、目标美术、对端视频和长时间性能未由此证明。服务端和其他工作区状态须在集成时以实际版本取证。

角色身份与关系数据和渲染资产解耦；原生或 Web 渲染器只是可替换适配器。视觉效果走独立层；舞台、摄像头和发送视频各自有独立渲染实例，语义可共用，不假定本地画面自动进入视频轨。保持既有 UI，纯决策层先写失败测试再实现。

## 4. 产品功能到责任边界

| 能力 | 事实来源及责任 | 外部依赖与边界 |
|---|---|---|
| 角色目录 | 内容服务维护 CharacterDefinition、版本、区域与权利；客户端只读取获授权版本 | 上下架、撤回、内容审核、授权有效期属于产品控制面 |
| 用户角色 | UserCharacter 持久化角色实例、昵称、声音、外观选择、配置版本 | 选择仅引用发布包与兼容规格；角色定义升级不覆盖用户配置 |
| 对话和记忆 | 会话服务负责 turn、版本与权限；记忆记录来源、有效性及删除状态 | 用户内容不进入日志标签；检索、缓存、派生和备份删除必须覆盖 |
| 语音 | RTC 抽象 + 可替换 STT/LLM/TTS provider；会话控制处理打断 | 音频与 cue 对齐播放器时钟；第三方数据保留和区域能力按合同验证 |
| 外观与特效 | `wardrobe-spec` 定义槽、候选、依赖冲突、状态及实际绑定；`cmp.cue` 路由特效 | 预览态和已保存选择分离；缺资源按回退显示，不虚报成功 |
| 工坊 | 自有控制面保存项目、任务、工件、权限、审批；Hermes 为候选执行器 | AI 给草稿/建议；确定性检查与授权人工审核决定发布 |
| 发布 | 服务端记录不可变 release、签名摘要、依赖、兼容矩阵、门禁和回滚目标 | 审核、灰度、下架和应急撤回独立权限，审计并留存 |

## 5. 技术路线对照

以下“建议”是实施优先级，候选库未做本项目生产验证。详情与逐项来源见两份调研；所有开源代码、引擎核心、模型、音频、字体和素材单独核对授权。

### 5.1 角色表现

| 方案 | 适合 | 成本与限制 | 选择 |
|---|---|---|---|
| Live2D Cubism Native | 插画角色、高表现力；已有 Android 接入 | 依赖高质量美术和绑定；Core、Editor 和模型分别授权；换装必须真实有部件/参数 | 首个高质量角色主线，先真实模型和目标机验收 |
| Spine 官方 runtime | 2D 骨骼、动作与组合 skin；已有 Web 样件 | 专用许可非 MIT；导出和 runtime 版本匹配；骨架与服饰须预先设计 | A/B 补充，移动端性能与授权通过后决定 |
| Three.js + three-vrm | 可旋转 3D、VRM 角色、场景和动作 | WebView/WebGL 2、透明合成、移动性能与材质兼容待验 | 3D 扩展实验，不挤占首个 Live2D 交付 |
| Filament | 原生 Android 3D 和长期性能对照 | 自建资源、材质和场景集成成本较高 | 当 WebView 满足不了实测门槛时比较 |
| Rive / OpenBone / Inochi2D | 交互动画或新资产产线 | 各自格式、创作流程与兼容性不同；不能无损替代现有资产 | 执行有限对照，不承诺统一导入 |
| 静态图 + 轻量动画 | 弱网、低端机与故障降级 | 无法替代最终角色表现 | 所有首发目标端必须保留的最低可用路径 |

Live2D Framework 与闭源 Cubism Core 分开审查；Spine Runtime 使用其专有授权。旧文档中如有“Spine runtime MIT”与此冲突，以固定版本官方协议为准。Umamo、Ayatsuri 为文件互通研究候选，仅使用复制资产，不能视为已证明往返无损。

### 5.2 视觉特效与摄像头

| 能力 | 基线 | 比较候选 | 决策依据 |
|---|---|---|---|
| 轻量舞台动画 | 现有 Lottie Android 独立层 | Rive、libpag、dotLottie | 设计师产线、跨端素材保真、包体、可控参数与许可；PAG 预编译包统计行为单独核验 |
| 粒子与复杂特效 | 先保留现有 Lottie | Konfetti（Android）、three.quarks/Proton（Web）、Effekseer（原生） | 同 cue、同视觉目标、目标设备实测画面与帧时间；无需全量集成 |
| 人脸和手部 | 现有 MediaPipe + CameraX debug 方案 | YuNet 仅作人脸框或其他备选 | 模型/权利、跟踪精度、耗电与隐私；检测框不是 478 点与表情追踪的等价替代 |
| 实时美颜 | 不默认启用 | GPUPixel；RootEncoder 作 GL 管线参考 | 同输入画质、ABI、16 KB 页、EGL 生命周期、帧同步及依赖审查 |
| 视频处理与输出 | 单独建立帧合成适配层 | Media3 Effect/Transformer、libyuv、LiveKit 自定义 capturer | 文件导出与实时通话分开；CameraX 格式、stride、旋转、颜色、帧所有权和延迟实测 |
| 诊断 | Perfetto | AGI/RenderDoc/Spector.js、Paparazzi | 真机系统轨迹、GPU 捕获、WebGL 与静态布局各覆盖不同范围 |

### 5.3 资产与语音工具

| 环节 | 候选与用途 | 不确定性 |
|---|---|---|
| 绘画/绑定 | Krita、官方 Cubism / Spine 编辑器，spine-scripts | 桌面软件和最终资产许可分开；人工分层和遮挡修复仍需做 |
| VRM 制作 | Blender + VRM Add-on、Character Studio、MPFB2 | 材质、表情、服饰、骨骼和来源素材逐项验收 |
| 动作 | VRMA、Rigger、VideoIntoBlenderModel | 动作权利、脚滑、手部与重定向质量；视频捕捉优先离线 |
| 口型 | 现有播放驱动基线；HeadAudio / three-vrm-lip-sync 对照；Rhubarb / LighterSync 用于预制音频 | 中文表现、Worklet、同步与模型许可；离线方案不等于实时通话 |
| 模型校验与压缩 | glTF Validator、glTF Transform、meshoptimizer、Draco、KTX、oxipng | 校验通过不代表 VRM 扩展正确；文件更小不等于加载更快或显存更低 |
| 制作编排 | 自有状态机与工具 + Hermes 候选 | 不把 Hermes 当作事实源、审批者或自动专业绑定器；先验证远程执行与恢复 |

### 5.4 语音、记忆与全球基础设施

| 决策 | 建议与比较 | 判断标准 |
|---|---|---|
| RTC | 现有 LiveKit 作为基线，其他 WebRTC 服务作受控对照 | 连接成功率、首音与打断 P50/P95、弱网、relay、并发成本、数据处理条款；不把历史预热收益当已验证 |
| STT/LLM/TTS | provider 接口隔离并保留第二供应商选项 | 按语言、口音、设备网络测质量与延迟；比较价格、区域、数据政策、故障降级 |
| 记忆 | 先以现有结构化记忆/关系库为基线，再比较专门的开源记忆系统与向量检索 | 以多语言召回、错记、纠错删除、租户隔离及成本评测；不开盲目迁移 |
| 存储与队列 | 复用已验证的关系库、对象存储和缓存/队列，控制面持久任务状态 | 以真实可用接口、区域策略、恢复与成本为准；队列不作唯一事实源 |
| 地域架构 | 区域配置和数据位置可切换；先确定首发市场再分阶段部署 | 延迟、可用性、成本、驻留及供应商合同；不把全球部署当现状 |
| 软件交付 | 原生运行/现有服务管理、可观测、构建与签名 | 不使用 Docker；每个发布包可追溯到来源与固定版本 |

## 6. 一次完整互动与接口契约

1. 用户选定角色实例与已发布资源，客户端核验 manifest、兼容范围和哈希，下载到临时目录，校验通过后原子启用；失败保留已知可用版本。
2. 创建会话时服务端授权实例与版本、签发最小权限 token；建立 RTC；UI 明确显示连接状态、麦克风与摄像头状态。
3. 音频或文字产生 `session_id / turn_id`；服务端检索用户授权记忆，生成文字、音频与符合白名单的表现意图。用户打断时取消正在处理的 turn 并拒绝迟到结果。
4. 客户端将 `cmp.cue` 映射为人物动作与独立特效，不识别的意图安全忽略；音频口型以播放时间为基准，参数不可用就回退。
5. 保存衣橱只写用户选择；版本化 `wardrobe-spec` 决定可选项、依赖、互斥与模型绑定，预览不覆盖已保存状态。换版本时映射失败显示缺失并回退，不悄悄购买或替换。
6. 退出时停止采集和任务；按照明确的用户设置与已发布的数据策略保留或删除，跨设备查看和删除应一致。

**目标契约，非现有 API 声明**：`CharacterDefinition(id, author, rights, locales)`；`CharacterRelease(id, engine, engine_version, assets[], checksums, capabilities, wardrobe_spec_version, min_client, licenses, qa)`；`UserCharacter(user_id, definition_id, release_id, settings_revision, wardrobe_selection)`；`Memory(id, owner, character_scope, source, confidence, inference, lifecycle)`；`Cue(schema_version, session_id, turn_id, sequence, intent, duration)`；`ProductionJob(id, input_version, tool_version, idempotency_key, state, artifacts)`。字段和协议应通过 ADR、schema 与兼容测试落地，不能通过示意 JSON 视为现有功能。

## 7. 内容生产、第三方引入与发布闭环

### 7.1 内容生产流水线

| 阶段 | 负责角色与输入 | 产出和通过门槛 | 失败处理 |
|---|---|---|---|
| 需求与权益 | 产品/制片：角色 brief、目标市场、参考图合法来源 | 可追溯 brief、风格及授权登记；用户提供的肖像需有明确使用权 | 缺失权利则暂停，不上传第三方服务 |
| 角色设计 | 美术 + 可选创作 Agent | 设定、服装分层计划、参数/表情/动作表，多语言名称；人工确认 | 记录反馈与新版本，不覆盖已确认资产 |
| 制作与装配 | 美术、绑定师；Cubism / Spine / Blender 等 | 源工程、分层、模型、图集、表情、动作及真实遮挡 | 工具只能辅助；修复和重新导出可重试 |
| 语音与动画 | 声音设计、语言审核 | 声音授权、样音、语言与语气，实时或离线口型配置 | 未授权或不同步不进入候选包 |
| 自动检查 | 构建/QA，固定版本检查器 | manifest、依赖、哈希、路径、格式、尺寸、参数、许可记录、恶意输入检查 | 失败有错误码和证据，不能靠 Agent 宣称通过 |
| 视觉/交互验收 | 美术、QA、无障碍与地区评审 | 固定动作/表情/衣橱/分辨率/设备截图录像；与目标参考盲测对比 | 动画缺损、遮挡错误或性能不达标退回 |
| RC 与审批 | 发布人、独立审核人 | 不可变候选包、兼容矩阵、SBOM/素材清单、签名和回滚版本 | 审批未通过不能进入可见目录 |
| 灰度和运行 | 运营、SRE、客服 | 按地区/设备/比例发布，观测失败、崩溃、首帧与投诉 | 触发阈值暂停、回滚、下架并保留证据 |
| 撤回与留存 | 内容治理、权益及数据团队 | 撤权、通知、缓存失效、用户替代选择、保留/删除记录 | 已下载离线包及衍生资产需有处理策略 |

### 7.2 第三方开源集成流水线

`需求与目标 → 现有能力核对 → 候选对照 → 许可证/权属审查 → 固定版本与依赖清单 → 隔离 PoC → 安全和隐私检查 → 统一接口适配 → 自动/设备/视觉验收 → 审批 → 灰度 → 监控/升级/撤回`。

每项形成记录：仓库 URL、commit/release、维护责任人、代码与传递依赖许可、NOTICE、模型/数据/素材权利、构建方法、ABI/平台、第三方服务和网络行为、威胁面、验收输入和输出、替代方案、回滚方案及复审日期。运行时依赖、离线制作工具和仅借鉴代码分开核算；GPL 等义务按实际分发方式审查。复制代码也须保留来源与许可。

外部模型、ZIP、插件和生成产物视为不可信：限制路径穿越、解压体积、文件类型、执行、网络、时长与资源，隔离工具权限；通过发布门禁后才进入正式资源。隐私数据不发往不符合用途和合同的数据处理方。

### 7.3 发布包与状态机

- 包包含 `manifest`、角色与格式版本、runtime 最低/最高兼容、依赖与 hash、资源大小、能力集、`wardrobe-spec` 引用、视觉/自动 QA 证据、地区语言、权利与过期信息、审批与回滚引用。定义 schema 后以测试验证，以上为提案。
- 状态：`draft → producing → candidate → qa → approved → staged → published → retired/revoked`；每次迁移由服务端鉴权、校验、幂等记录。失败回到对应阶段并保留证据，撤权独立可触发紧急下架。
- 工作流执行器以输入版本、租约、超时、取消、幂等键和工件 hash 实现重试；数据库是权威状态，队列仅调度。关键发布需双人职责分离，agent 无直接发布权。
- 应用与资源独立版本化；灰度时旧客户端保持可用，发布前演练资源 CDN 失效、坏包、旧 schema 和回滚。迁移先兼容旧版本，再分阶段收紧；撤回不能删除用户关系或私有记忆。

## 8. 全球化、信任与运营

- **地区能力矩阵**：按国家/地区记录语言、真实可访问的 STT/TTS/LLM、RTC relay、存储位置、最低年龄和内容规则、支付、客服、商店要求、紧急资源及负责人；只有逐项核验通过后启用对应地区。避免将某地区法律直接推广全球。
- **本地化**：界面字符串、角色称呼、人称代词、日期/数字/时区、RTL、字幕与屏幕阅读；翻译与语音以母语评审和真实音频集验收。用户可自行设置语言与内容偏好，不从姓名推断性别。
- **信任与隐私**：摄像头、麦克风、记忆、上传、语音克隆及对外共享各自单独选择；显示用途、保存期限和第三方处理。公开角色发布需要肖像、IP 与音乐权利；举报、申诉、撤回、紧急下架和客服渠道可用。
- **安全与边界**：明确不是人类，处理误导、冒充、未成年人和危机；保护真实人际关系，不按依赖程度优化推荐。各市场由法务对照当期原始法规、年龄与商店政策，不将历史研究当成当前法律结论。
- **商业可持续**：控制单位会话的模型、TTS、RTC 带宽与存储成本，透明展示订阅和限额；不以限制基本隐私控制或诱导依赖为收费策略。定价和首发地区待用户研究与成本测量后决定。
- **运营**：创作者审核与投诉 SLA、资源权利过期提醒、故障值班、跨语言客服、版本公告、灰度及事故复盘；每项先指定负责人再开放公共生态。

## 9. 测量、验收与风险

以固定素材、目标设备矩阵、网络条件和版本记录基线；确定数值前不虚构达标门槛。每项记录 PASS/FAIL/BLOCKED、输入、截图/日志、构建版本与责任人。

| 类别 | 验收方式 |
|---|---|
| 陪伴质量 | 多语言真实用户评测，关注理解、角色一致性、记忆可纠错、用户自主与有害回应；不使用停留时长作为唯一成功指标 |
| 语音与可靠性 | 首音和整轮延迟 P50/P95、打断成功率、弱网恢复、错误结束率；人工判断同步和自然度 |
| 视觉 | 相同授权角色和参考目标盲测；固定表情、动作、镜头和换装组合；缺失资产不得显示为可用 |
| 渲染 | 同场景测首帧、帧时间 P50/P95、CPU/GPU、内存、温升和电量；透明、前后遮挡与后台恢复真机验证 |
| 记忆与安全 | 双用户/多角色隔离、删除后不召回、权限撤销、数据导出、恶意资源、审核与恢复演练 |
| 发布与运营 | 从素材来源到工件 hash、审批、灰度、监控、撤回、旧版本恢复；真实故障注入与审计 |
| 全球体验 | 母语与文化评审、字幕/屏幕阅读、网络与设备分层；不把一个地区结果推广全球 |

主要风险：真实角色美术产能不足；授权或素材权利不完整；WebView 合成和 GPU 成本；语音延迟/打断或服务单点；记忆错写和删除遗漏；多地域政策、支付和客服未准备；工坊依赖人工工具无法无头执行。每项风险必须有负责人、验证证据、降级与重新评估条件。

### 当前实现边界及需要对账的事项

- 当前工作树的完整 Live2D 换装仍有 ATRI 专属逻辑；生产侧 `wardrobe-spec` 及检查工具存在，但贯通任意原创模型仍是 P1-03。衣橱文档的 pending 数量与文字描述存在不一致，以实际 spec 和模型核验为准。
- 引擎资源安装机制与分层头像包已有部分 hash、暂存和失败保护；前者 hash 在部分路径可选，不应描述为统一强制签名发布。完整生产控制面、审批和可撤回目录仍是目标设计。
- 当前舞台特效锚点部分为视口固定位置；跨角色姿态贴合、相机和对端视频仍需独立验证。RTC 的 SDK 方法存在不等于现有工程已发送自定义视频。
- 三份原产品方案为讨论稿，本文的 Android 优先、首个 Live2D 角色及阶段排列是建议，不是已确认商业或首发决定。真实 provider、首发市场、保存期、设备矩阵、数值门槛和责任人待立项确定。

## 11. 可扩展机制与决策记录

- 每增加一个引擎、模型、声音、语言、记忆 provider、特效或地区，都先声明能力、版本、权利、依赖、降级、质量门槛和负责人；只通过稳定适配器挂入，不直接改写用户关系或其他引擎的数据。
- 新想法进入探索池：写明用户问题、可证伪假设、受众、依赖、风险、最小实验与停止条件；通过之后进入对应阶段任务。实验结果包括失败和 BLOCKED，避免把候选库堆成必须全部上线的依赖。
- ADR 至少覆盖首发市场、角色主线、媒体供应商、记忆模型、资源 schema、工坊执行器、存储区域和视频共享；记录选项、证据、成本、责任人、复审时间。公开生态、原创角色数和商业模式留给真实测试与产品决策。
- 首轮具体执行顺序：P0-01/02/03 并行取证 → P0-04/05 和 P0-06 → P0-07 验收；P0-08 同步澄清对象；随后推进 P1 记忆与衣橱。工坊与新渲染器可先做只读评估，但生产发布依赖角色和权利闭环。
