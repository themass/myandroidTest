# Google Play 头部 VPN 竞品：留存与停留设计对照（2026-11-12）

调研范围：Proton、NordVPN、Surfshark、ExpressVPN、Windscribe、hide.me、Hotspot Shield、Psiphon、Hola、Planet VPN、Turbo VPN、VPN Proxy Master、Thunder/Secure VPN、Super Unlimited Proxy、X-VPN、Urban VPN。
资料来自官方帮助页、更新日志、评测站与 Play/App Store 评论。Play 页面无法直接抓取，相关说法为转引；标"未核实"的不要当事实用。

## 1. 先纠正目标：VPN 不该追求"前台停留时长"

- 头部 VPN 的设计都在**缩短**打开应用的时间（一键连、自动连、widget），用户留下来的方式是"VPN 一直连着"，而不是"一直盯着 App"。
- 应该分开看三个指标：
  1. **已连接时长**（每日/每用户）——核心价值，广告型免费 VPN 的收入也和它挂钩；
  2. **回访**：D1 / D7 / D30、每日打开次数；
  3. **前台时长**：只在有真实内容（测速、体检、统计）时才有意义。
- 没找到 VPN 品类专属的留存基准。全品类参考：D1 约 21–25%，D7 约 8%，D30 约 3–4%；Android 应用 30 天内卸载率约 46%（AppsFlyer / UXCam 2026）。
- 本地已经有 `ConnSession`（每次连接的时长与流量），但服务端没有汇总，所以现在**算不出上面任何一个指标**。这是第一件要补的事。

## 2. 头部普遍有、我们没有的

| 模式 | 谁在做 | 我们的现状 |
|---|---|---|
| 一键连到"智能/最快"节点 | ExpressVPN Smart Location、Turbo、Proton 免费层 | 有 Best/Auto，但在列表页里，首页大按钮连的是"当前选中" |
| 最近连接 / 收藏 / 置顶 | Proton、ExpressVPN（最近 3 个 + 推荐） | 无 |
| 按网络自动连接（未知 Wi-Fi 自动开） | NordVPN、Surfshark、Windscribe（逐个 Wi-Fi 设规则） | 无 |
| 桌面 widget 一键连 | Proton、ExpressVPN | 无（设计文档写"Quick Tile 已有基础"，代码里实际没有） |
| 连接后的价值展示：拦截数、节省流量 | Proton NetShield | 无；连接后首页没有计时和流量 |
| 泄露监测 + 推送 | NordVPN Dark Web Monitor、Surfshark Alert | 网络体检只查出口 IP 归属 |
| DNS 层广告/追踪拦截 | Nord、Surfshark、Express、Proton、Windscribe | 无（政策风险见第 4 节） |

## 3. 我们有、头部没有的

- 看激励视频得观看券、券换 VIP 时长、邀请码双方得券：这是长尾免费 VPN 的打法。头部唯一类似的是 Psiphon 的 PsiCash（看广告换限时加速）。
- 已有 SSV 服务端校验，比多数长尾应用规范。保留，但不要把它当主要留存手段。
- **每日签到 / 连续登录**：头部一家都没有，没有证据说明它对 VPN 有效。不建议优先做。

## 4. 政策红线（做之前必须确认）

- **VpnService 政策**：VPN 必须是核心功能，需要在 Play Console 提交声明；禁止为了变现重定向或操纵其他应用的流量，**禁止操纵广告**。DNS 拦广告这一项，头部在 Play 上确实在做，但对一个靠 AdMob 变现的免费 VPN，"拦别人家的广告"在审核上风险更高。建议只拦**追踪器和恶意域名**，不拦广告，或者只给 VIP、默认关闭。
- **AdMob 激励广告**：必须用户明确点"是"才能播；激励插屏要有介绍屏和"不要"选项。违反会以"Rewards implementation – User choice"为由被限流。
- **Better Ads**：禁止用户操作中途意外弹出的插屏；全屏插屏 15 秒内必须可关。多家广告型 VPN 在"点 Connect 之后"弹插屏，这种做法有被认定为意外广告的风险。**需要确认我们自己的连接流程里有没有这样的插屏**（本次没有核对）。

## 5. 建议（按投入产出排序）

**P0：数据已有或改动很小**
1. **连接状态卡**：连接后首页显示计时、本次流量、当前延迟；断开后显示"本次保护时长"。数据来自 `SessionRecorder` / `ConnSession`。
2. **用量统计页**：今日、本周的已连接时长和流量，按天的柱状图，同样复用 `ConnSession`。这就是 Proton NetShield 那类"价值展示"的平替，而且不碰广告政策。
3. **最近连接 + 收藏**：列表页顶部放最近 3 个节点，支持星标收藏。
4. **埋点上报**：每天的已连接时长、打开次数、D1/D7 回访，以及测速、体检等功能的使用率。不做这个，下面所有改动都没法评估。

**P1：一两周的工作量**

5. **快捷设置磁贴 + 桌面 widget**：显示连接状态，一键连接或断开。
6. **首页大按钮默认连"智能推荐"**：按延迟和最近成功率选节点；用户手动选过的节点优先。目前的 ping 结果和 `TunnelMtuPolicy` 里记录的成功次数都可以拿来用。
7. **原生测速 + 泄露检测**：放在 Tools 页，扩展现有的网络体检，加上 DNS 泄露、WebRTC 检测和测速，测试结果可以分享，带邀请码。
8. **未知 Wi-Fi 自动连接**：按 Wi-Fi 记规则。要注意 Android 14+ 的前台服务限制和 `VpnService.prepare` 的授权要求，需要先做技术验证。

**P2：先确认政策再决定**

9. 追踪器、恶意域名拦截，以及对应的拦截计数（见第 4 节）。
10. 每周报告推送：头部没有先例，可以等埋点数据出来后再决定做不做。

## 6. 明确不做

- 假倒计时、强制看广告才能连接、误导性按钮（与现有 `REWARD-AND-RETENTION-DESIGN.md` 7.4 的原则一致）。
- 为了拉长前台时长而塞进去的资讯、外链内容。VPN 用户来这里是为了连上就走，硬留他们只会提高卸载率。
