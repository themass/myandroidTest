# 拍照解题「一直提示边框、就是不拍照」· 取证与修复

日期：2026-11-23 设备：vivo V2279A `10CE7P1G56004B7`

## 用户报告

> 拍照解题一直不对，提示边框之类的，就是不拍照，题都是对的

## 取证（不是猜测）

1. **快门确实按过 4 次**。`run-as com.openapi.ks.chat ls cache/`：
   `paizhao_capture_1795444810865/…814117/…897496/…934956.jpg`，22:40~22:42，各 4~8 MB。
2. **一次都没提交**。`files/photosolve_history/` 目录 22:40 建好，`img/`、`thumb/` 全空
   → 4 次全部卡在检测之前，从没走到 Recognizing。
3. **照片内容**：把 4 张原图拉下来看 —— 用户拍的是**屏幕里的题目**（电脑/手机屏上的
   二元二次方程练习题）。题是对的。
4. **把同一批图喂给随包的检测模型重跑**（`app/src/main/assets/docquad/docquadnet256_trained_opset17.ort`，
   与 `DocQuadNetCropAssistProvider` 完全同一份 letterbox/预处理）：

   | 图 | 四个角点过 `sigmoid ≥ 0.5` 的个数 |
   |----|----|
   | …810865 | 0 / 4（sigmoid 0.049~0.366） |
   | …814117 | 1 / 4 |
   | …897496 | 3 / 4 |
   | …934956 | 1 / 4 |

   `CornerHeatmapDecoder` 的规则是「任一角落在门槛下，整次检测判负」→ 每次都判负。
   DocQuadNet（makeacopy）只在**真实纸面**上训练过，翻拍屏幕它认不出四角。
5. 质量闸门不是元凶：对默认 80% 框的裁剪结果复算，
   `sharp=697~1293`（阈值 60）、`luma=163~182`、`issues=[]` → 不会弹「不够清晰」。

## 根因

判负之后，状态机把用户**退回取景页**（`step = Capture`）并显示
「画面里没找到题目，请把题目放进取景框后再拍」。图被丢掉，只能重拍；
重拍还是判负 → 界面死在这条提示上。用户看到的就是「一直提示边框、就是不拍照」。

端上这道闸门按设计只做**几何**预筛，「是不是题目」由服务端判（40002）。
所以它没有否决用户的资格，却事实上把用户挡住了。

## 改法

- `CaptureFlow`（`QuestionFrameCheck.kt`）：把「检测完落到哪一页」抽成一张可测的表。
  **任何结果都不退回取景页**：Found→四角微调；NotFound→四角微调（默认框，手动拖）；
  DetectorUnavailable→旧手动框选。
- `PhotoSolveViewModel.onPhotoCaptured` 走这张表；判负时打一行 `PhotoSolveQuad` 日志。
- 服务端回 40002 时也不再退回取景页，改回四角微调页，用户把框拖准再提交。
- `QuadAdjustScreen` 新增 `notice`：框不是自动找到的时候明确说明，
  否则用户会奇怪「框为什么不对」（新文案 `photosolve_quad_no_auto`）。
- `onCropCancelled` 回取景页时清掉陈旧的 `frameCheck`（原来会挂着一句已经没有意义的提示）。

## 真机要验（装机由协调会话做，我不给 V2279A 装机）

| # | 操作 | 期望 |
|---|------|------|
| PS1 | 拍**屏幕里的题目**（复现用户场景） | 检测判负后**不再**退回取景页：进四角微调页，顶部有黄色说明「没自动找到题目边框…」，四个角和四条边都能拖 |
| PS2 | 在 PS1 的页面上把四角拖准 →「裁剪并识别」 | 走到 Recognizing → 出结果；`files/photosolve_history/img/` 里出现记录 |
| PS3 | 同一页点「自动识别」 | 再跑一次检测；判负也不退出这一页 |
| PS4 | 拍**真实纸张**上的题 | 仍自动贴合边框（无黄色说明），行为不变 |
| PS5 | 结果不对/服务端 40002 | 提示后回到四角微调页（图还在），不用重拍 |

## 已知遗留（不在本次改动内）

- **模型对翻拍屏幕无能为力**：DocQuadNet 数据集是纸面。现在的修法是把决定权交回用户
  （手动拖角），不是让它认屏幕。要真正自动贴合屏幕，需要给模型补屏幕样本或加一条
  「高亮矩形」几何兜底 —— 属于算法切片，未做。
- **40002 不退额度**（服务端 `PhotoSolveController`：只有 50001 退）。用户被几何闸门放行后
  更容易撞上 40002，一次 40002 就烧一次额度。是否退款是服务端产品决定，留给协调器。
