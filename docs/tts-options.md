# 助手回复朗读（TTS）方案，待你选择

## 现状（已核对代码）
- 已有后端 TTS：`ChatRepositoryImpl.synthesizeSpeech` 调 `/chat/ai/tts.json`，返回音频后存到 `files/tts/`，再由 `AudioPlayer` 播放。
- 设置页有"TTS 开关"（`CommonConstants.TTS_OPEN`），新回复自动播报走这条链路。
- 设备自带 TTS（`android.speech.tts.TextToSpeech`）：**代码里没有接入**。

## 方案 A：设备优先，后端兜底（我的推荐）
- 朗读时先用设备自带 TTS：离线、免费、不耗服务端额度、延迟低。
- 设备 TTS 不可用（没有中文语音包）或失败时，回退到后端 `/chat/ai/tts.json`。
- 代价：不同手机的音色和质量差别大，中文语音包可能需要用户自己装。
- 工作量：新增一个 `DeviceSpeech` 封装（初始化、语言检查、朗读、停止），`ChatViewModel` 朗读入口先试设备，失败再走现有接口。

## 方案 B：只用后端 TTS（维持现状）
- 音色统一、质量稳定，不依赖手机语音包。
- 代价：每次朗读都走网络，消耗服务端额度，离线不可用。
- 工作量：几乎为零，现有代码已经能用。

## 需要你选
1. 选 A（设备优先 + 后端兜底），还是 B（维持后端）？
2. 如果选 A：设备 TTS 的音色如果比后端差很多，是否接受"只在设备没有中文语音时才用后端"？

## 不做的事
- 不改"语音消息点朗读等于播放原声"的逻辑（SPEC2b 已定）。
